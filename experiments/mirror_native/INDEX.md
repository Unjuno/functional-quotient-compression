# Mirror-native experiment index

Large local evidence bundles are not committed to ordinary Git history. SHA-256 values below identify the verified local evidence packages.

| Experiment | Main question | Canonical status |
|---|---|---|
| MN001 | Can a tiny causal Transformer learn input-dependent shared states? | Feasibility only. |
| [MN002](mn002_20261003/README.md) | Do a few shared states help at matched resources? | Mixed. |
| MN003 | Can block routers run as one packed computation? | Yes numerically; CPU loop overhead reduced. |
| MN004 | Do overlapping supports and averaging help? | Not consistently. |
| MN005 | Can where-routing use a candidate region bank? | Cost reduction with quality/runtime tradeoffs. |
| MN006 | Is router early lock-in the main bottleneck? | Strong version not supported. |
| MN007 | Can semantic concepts self-organize into shared bases + Mirror states? | Weak spontaneous grouping; no Mirror-specific advantage. |
| MN008 | Does functional recombination supervision create reusable factors? | Strong improvement, but additive control remains strong. |
| MN009 | Can shared Dense computation replace duplicated experts? | Beats narrow same-budget soft-MoE; not generally Dense-superior. |
| Analytic bridge | Can global Mirror states be added without breaking the current function, and how do count/breadth differ? | Function-preserving split derived and numerically checked. |
| MN010 | Can one Dense model dynamically grow global Mirror states? | Broad states show a discovery signal; replication mixed; count alone not enough. |
| [MN011](MN011_PLAN.md) | What matters more: state breadth or state count? | **Pre-registered next experiment.** |
