# MLP-HYBRID-001 — Mirrorの有効領域を出力補正で再検査

日付: 2026-10-17。状態: **合成ではない手書き数字のMLP機構研究。採用保留／有望領域の絞り込み**。Transformer・自然言語・実MoEの実験ではない。

## 1. H — 問題設定

前回MLP-ROLE-001では、gate×up Mirror は手書き数字の4属性分類で同容量gainを上回ったが、**通常のタスク別出力ヘッドがMirrorより軽くて高精度だった**。自然画像の復元ではnative gain/readoutの方が良く、汎用性も未証明。今回、「Mirror＋小さな私有出力補正」でその不足を補えるかを、純nativeの同補正、タスク別出力ヘッド、独立MLPと区別して試す。

基本構造：

\[
 g=xW_g+b_g,\quad u=xW_u+b_u,\quad
 f_{ij}(x)=\mathrm{SiLU}(gR^g_i)\odot(uR^u_j),\qquad
 y_{ij}=f_{ij}W_d+b_d+\Delta_{ij}(f_{ij}).
\]

- `mirror`: \(R\) は2軸のGivens回転。`gain`: 同数パラメータのチャネルgain、`tied`: 共通特徴のみ。
- `base`: 追加の出力補正なし、`bias`: pairごとの出力バイアス、`rank2`: 共有2次元出力基底とpair別係数、`full`: pair別の完全なdown重み補正とバイアス。
- `pair_readout`: nativeの共有gate/upと4つの出力射影。`independent`: 4つの独立MLP（品質の上限対照）。

## 2. T — 検証手順

- sklearn手書き数字1,797サンプルを新しい乱数分割（訓練60%・検証20%・テスト20%）。4種の数字属性分類（BCE）と、ノイズ付き画像の4領域再構成（MSE）を**別の用途**として測定。
- 開発90600の実装確認後、ソース／テスト／プロトコルSHA-256を先に固定。主評価**5独立分割×2初期値×2用途×11方式＝220モデル**。AdamW, LR0.012, WD0.01, batch64, 550更新。評価時刻110,330,550。基準は**検証損失で選ぶcheckpointのテスト誤差**であり、テストを使った最適停止はしない。
- 本評価後に別ロックを作成し、**新しい3分割×2初期値×2用途×5方式＝60モデル**、1,400更新（300,550,900,1400）を実施。後から設計した追補であり、主実験の事前判定を修正しない。
- 学習共有親重みとミニバッチ抽出列を揃え、モデル固有の追加学習パラメータはすべて保存容量・パラメータ数へ課金。全4論理出力を同時に計算する密方式。実MoE疎ルーティングでもGPUでもない。
- 事前固定したgateの中心は、`mirror_rank2` が `gain_rank2` を平均品質5%以上かつ最悪タスク品質を悪化させず、**5世界中4以上**で上回るか。より小さな`pair_readout`を上回るかも必須確認。

環境：CPU、Python3.13.5、PyTorch2.10.0+cpu、NumPy2.3.5、scikit-learn1.8、FP32、各CPUワーカーBLAS1スレッド、CPUクロック非固定。等更新回数と等計算量は別。

## 3. D — 実測結果

主評価の値は「各分割で2初期値平均→5分割の中央値」、低いほど良い。

### 数字の4属性分類、テストBCE

|方式|テストBCE|学習パラメータ|推論保存量（実バイト）|
|---|---:|---:|---:|
|Mirror単独|0.07267|3,177|15,949|
|gain単独|0.08734|3,177|15,949|
|Mirror＋pair bias|0.07281|3,181|16,201|
|Mirror＋rank2出力補正|0.07680|3,233|16,581|
|gain＋rank2出力補正|0.08867|3,233|16,581|
|**Mirror＋full pair出力補正**|0.06904|3,277|16,773|
|gain＋full pair出力補正|0.07387|3,277|16,773|
|**通常pair別出力ヘッド**|**0.06884**|3,220|**15,573**|
|4独立MLP|**0.06523**|12,580|52,949|

- Mirror単独／通常pair-readoutの分割別誤差比は `0.930,1.218,1.060,1.148,1.288`、改善は1/5分割。Mirror単独はnative gainに有利な傾向だが最良nativeには及ばない。
- `mirror_rank2/gain_rank2` の分割別比は `0.866,1.126,1.011,0.961,0.894`。所定の「5%改善＋最悪タスク劣化防止」ゲートは**FAIL**。`mirror_rank2/pair_readout` の比は `1.116,1.145,1.161,1.113,1.025`（Mirrorが0/5分割で劣る）。
- `mirror_full/gain_full`の世界中央値比は約0.895、4/5分割で改善したが、**5%以上の改善は3/5**にとどまる。Mirror+full／pair_readoutの中央値比は約0.984だが、前者は**約7.7%保存量が大きい**。nativeを凌ぐ費用対品質フロンティアは**未成立**。
- `mirror_rank2/mirror_base`の改善が安定せず、簡単なrank2追加が万能な対策ではない。

### 長時間追補（3新分割・1,400更新・検証選択checkpoint）

- 数字属性分類：Mirror単独 vs pair-readoutは**0/3分割**。Mirror＋full対gain＋fullは1/3、対pair-readoutは2/3、**一貫したフロンティア改善なし**。
- 画像復元：Mirror＋full対gain＋fullは1/3、対pair-readoutは2/3。一律のMirror優位なし。
- 最終1,400更新だけを選ぶのではなく、300/550/900/1400の検証最良を使用。前のMLP-ROLE-001でも過剰学習が観測されたため、長期更新で必ず勝つという推論を避ける。

### CPU forward（単一スレッド、batch64、5群×300回、各群40 warmup）

属性分類の中央値：Mirror単独0.1253ms、Mirror＋rank2 0.1603ms、Mirror＋full0.1594ms、native pair-readout0.0326ms、4独立MLP0.0756ms。これらは未融合Eager PyTorchであり最適化ハードウェアの下限ではない。**実測ではMirrorを高速とは呼べない。**

## 4. 監査

- **11単体テスト合格**。主評価220件×最終/検証最良＝440個、追補60件×2＝120個の保存推論ペイロードについてSHA-256、実保存バイト、PyTorch読出しと別実装NumPy FP64で値・損失を照合。主最大損失差3.27e-8、追補2.92e-8。ソース事前ロック一致。
- 主評価3件の完全再学習で全チェックポイント・保存テンソルSHA完全一致。**同環境の再現確認であって独立第三者追試ではない**。
- 監査対象は小型SwiGLUであり、自然言語LLM、GPU、KVキャッシュ、ルーティング、Transformer NLLは未試験。

## 5. C — 対立仮説と、どう使うか

1. **タスク特化が出力側だけで足りるなら、Mirrorを入れない。** 数字属性分類では共有特徴＋タスク別readoutがより小さく速い。鏡像のgate/up追加に費用対品質の価値はなかった。
2. **下流で非線形なgate/up相互作用が必要な場合だけ、Mirrorを候補にする。** 構造的に一致する合成教師・組み合わせ未学習テスト（DMFFN-001）や剰余演算遅延汎化（GROK-001）は探索継続の根拠だが、自然ラベルでの独自優位を保証しない。
3. **独立性の高い用途はnativeを優先。** 画像4領域の再構成、回帰、短期の時系列ではMirror利得がなかった。
4. **容量調整はMirrorの角度数だけで決めない。** 候補にnative readout / gain / rank1-2補正 / private residualを同時に置き、検証損失改善÷実保存バイトおよびactive FLOPsで選ぶ。
5. **比較は学習曲線と評価時点で行う。** 短期学習では不利なMirrorが改善する事例はあるが、今回の少標本自然課題では長期更新が汎化を悪化させる場合もある。

## 6. U — 不確かさ／次の検証

5分割は**同じ1797枚の手書き数字**の異なる分割であり、独立した5つの現実問題ではない。画像属性ラベルは元の一つの数字から作った4属性で、用途の広さは限定される。良好なBCEにはhead-specific biasやreadoutで十分な可能性が強い。推論速度はCPU実装とクロック変動に依存。統計推論では世界（分割）単位とし、2初期値を独立世界扱いしない。

**次の優先課題：** あらかじめ別々の実データタスクで学習したFFNをfeature/channel整列した上で、(i) native readout・gainで吸収できる差、(ii) gate/up Mirrorがはじめて吸収できる差、(iii)必要なprivate residualを分ける。別の自然な言語タスクでも、同じチェックポイント選択・同容量・同FLOPsを満たすまではTransformerへ推奨搭載しない。

**ERROR CHECK:** 組合せ数と独立機能容量、合成教師と自然データ、BCEとMSE、更新数と学習計算量、良い分類精度と同品質保存利得を混同しない。過去の実験判定・mainを変更しない。
