# DMFFN-003：自然画像で学習したFFN群のMirror共有・組み合わせ汎化・学習量の実験

**実行日：2026-10-17。コンテナCPU、合成Mirror教師だけに依存しない新規検証。**

## 0. 結論（範囲限定）

**Dual-Input Mirror SwiGLUは、自然な手書き数字画像の9分類機能を少ない保存バイトで学習できたが、自然に個別学習したMLP群の未知の組み合わせへの転用と、同容量の強い通常方式に対する品質上の優位性は実証できなかった。** さらに少数データに対して6,000更新まで延ばすとテスト損失が悪化した。旧DMFFN-001の整合合成教師上の肯定結果はそのまま保持し、今回は新たな外的妥当性の壁として扱う。

最も重要な比較：9組全教師ラベル学習のテストBCE中央値は、共有Mirror **0.089662**、同容量gain **0.091273**、ほぼ同容量pair専用出力ヘッド **0.039903**、独立9MLP **0.031991**。Mirrorのモデル部分は20,489 B／4,270パラメータ、独立は153,685 B／37,737パラメータと小さい一方、独立との同等品質ゲートは0/3世界で不合格。後付けの未知組み合わせへの汎化は完全共有MLPより大幅に悪い。

## 1. H：仮説

- H1: Mirrorに都合よく作った教師を使わず、実画像から別々に学習した9個のSwiGLUの機能を3組gate×3組upの構造で共有できるか。
- H2: 9組のうち6組を学習すれば、残る3組のgate/upを未学習で合成できるか。
- H3: native factorized gain・同バイトpair Mirror・通常のpair別出力headを上回るMirror固有の利得があるか。
- H4: 固定した学習更新数の増加で独立MLPとの精度差が閉じるか。

## 2. T：データ、実装、フェーズ

- データ：`sklearn.datasets.load_digits()`、8×8実手書き数字画像、1,797画像、64入力特徴。元画像のpixelを0..16で正規化し、分割世界の**学習splitだけ**から標準化係数を計算。
- ラベル：3種類のA属性（偶数、素数、4以上）と3種類のB属性（集合に含まれるか）のANDによる9二値タスク。9組すべてに正例を含む。これは**人為的に構成した自然画像上のタスク**であり、自然発生した専門家ルーティングではない。
- 学習・検証・試験：層化60%/20%/20%、1世界当たり1,078/359/360画像。3新分割世界×2初期値。3世界は異なるデータ分割だが全て**同じ元の1797画像**を用いるので、3個の独立コーパスではない。
- 9独立教師：同じ64→32→1のSwiGLUを9タスクに個別の全重みで教師学習。最適化はタスク別に完全分離したテンソルを並列化した実装、AdamW lr0.01、800更新、batch64。試験平均正解率98.73%～98.92%（3新分割世界）。教師重みはMirror生成ではない。各教師の評価用ロジットは未学習3組について生徒訓練・モデル選択に渡さない。
- 生徒：共有64→32 SwiGLUのgate/upの先頭12個の2次元Givens平面、3 gate座標×3 up座標＝9機能。native gainも同じ72個の座標と同じ入力重み・バッチ列。pair Mirrorは9組×各gate/up4座標で**同じ72個**。pair-readoutは共有gate/upにpair別出力投影。tied共有と独立9個も対照。初期バイアス条件と全パラメータを推論bytesに課金。
- 学習世界とLR：ステージA開発世界79010、候補0.005/0.015で方法横断の訓練済み6組の検証教師-KLを最小化し0.015を固定。その後3新世界79021–79023×2初期値×6方式×1,800更新＝**36学習モデル**。
- ステージB：Aの結果を見た後に別プロトコルを設計。教師の出力ではなく6組の実ラベルのみで学習し、3組は完全文字通り未学習。開発79110でLR0.005を決定して固定。新世界79121–79123、36学習モデル、2,400更新。
- ステージC：A・Bの結果後に別プロトコルを設計。9組すべての実ラベルを学習し、**既知機能圧縮**だけを評価。開発79210でLR0.005を固定、世界79221–79223、36学習モデル、2,400更新。
- ステージD：C後に別プロトコルで固定、世界79321–79322×2初期値×3方式（Mirror, gain, independent）＝12学習モデル、6,000更新、途中900／2,400／6,000測定、lr0.005。
- 主要評価：試験binary cross entropy（BCE、低いほどよい）、accuracy、worst-pair BCE、学生教師ソフト分布KL（Aのみ）、実`torch.save`推論payload bytes、CPU更新と壁時間。テストデータはパラメータ更新やLR選択に使用しない。ファイルハッシュは各fresh前に固定。
- 観測環境：Python 3.13.5、PyTorch 2.10.0 CPU FP32、scikit-learn 1.8.0、NumPy 2.3.5、単一スレッド、GPUなし。クロック固定なし。訓練FLOPs精密値は未計測、同更新≠同時間。

### 2.1 パラメータ・容量（ステージC実測）

**重要な事後の保存量監査修正：** 以下の表はモデルの`torch.save`重み＋設定メタデータの実測値であり、入力を学習データの平均・標準偏差で標準化する状態は含まない。後処理監査で各世界に学習データから求める平均64個・std64個をFP64と設定込みで**2,917 B**の別の`torch.save`実payloadに保存し、前処理後の各全splitの入力テンソルが完全一致することを14世界で検査した。したがって**完全な入力前処理込み推論一式**はMirrorが**23,406 B**、通常gainも23,406 B、pair-readoutが**23,734 B**、独立9MLPが**156,602 B**である。前処理を含む削減率は**85.05%**。実験時の`20,489 B / 153,685 B = 86.67%`はモデル部分だけの比較としてのみ残す。モデル種類間で同じ前処理が使われるが、保存量から無料として除外はできない。


|方式|学習可能パラメータ|実推論bytes|
|---|---:|---:|
| 完全共有tied|4,198|19,729|
| **Dual-Input Mirror12**|**4,270**|**20,489**|
| 同サイズnative factor gain12|4,270|20,489|
| 同サイズpair-specific Mirror4|4,270|20,489|
| 通常shared+pair-specific出力head|4,454|20,817|
| 9独立SwiGLU|37,737|153,685|

Mirror対独立の**モデル部分だけ**の削減率は86.67%、前処理込みの完全推論状態は**85.05%**削減。ただしどちらも**同品質ではない**。また前に報告したDMFFN-001の5,081 Bは別の8入力→24内部→8出力モデルであり、直接比較禁止。

## 3. D：本評価結果（世界内2 seed平均→独立3世界の中央値）

### A：9個の個別学習FFNのlogitを6組だけ蒸留（1,800更新）

|方式|見た6組 test BCE|未学習3組 test BCE|未学習3組accuracy|
|---|---:|---:|---:|
|完全共有tied|0.5052|**0.6841**|61.9%|
|Mirror|0.0720|2.4891|69.4%|
|同容量gain|0.0611|3.2477|75.9%|
|同容量pair Mirror|0.0817|4.2956|62.0%|
|pair readout|0.1310|3.7287|51.8%|
|独立学生MLP|**0.0344**|0.6954|49.3%|

Mirrorの未学習BCEはgainより3/3世界で小さい（Mirror/gain比：0.693, 0.762, 0.766）。元の狭いgain比較の登録判定は見た6組の劣化制約を含め2/3世界で通過した。しかし**完全共有tiedより悪いのは3/3世界**で、Mirror/tied比は2.45～3.75倍。したがって「有用なゼロショット組み合わせ能力がある」は今回のデータではFAIL。同じ世界でaccuracyが比較的高くBCEがひどく悪いことは、特定の間違いを過度に確信していることを示す。

### B：実画像の二値分類を6組だけ直接訓練（2,400更新）

|方式|学習済み6組 test BCE|未学習3組 test BCE|
|---|---:|---:|
|完全共有tied|0.5091|**0.6869**|
|Dual Mirror|**0.0962**|3.0923|
|native gain|0.1263|3.8596|
|pair Mirror|0.1895|7.3928|
|pair readout|0.0584|2.3390|
|9独立学生MLP|0.0389|0.6930|

Mirrorはgainより未学習BCEが小さい3/3世界だが、**完全共有より悪い3/3世界**。直接ラベル学習でも根本問題が解消しない。事前固定した通常ゲート・共有モデルとの共同成功ゲート**0/3 FAIL**。Aの結果を見て設計した独立追補であり、Aの後付け「確認」と呼ばない。

### C：9組すべてを学習し、既知機能を圧縮（2,400更新）

|方式|全9組 test BCE|全9組accuracy|worst pair BCE|
|---|---:|---:|---:|
|tied|0.5480|73.23%|0.6599|
|**Dual Mirror**|0.0897|98.55%|0.1802|
|同容量gain|0.0913|98.26%|0.1981|
|pair Mirror|0.1998|97.39%|0.3114|
|**pair readout（+328 B）**|**0.0399**|**98.95%**|0.0825|
|9独立MLP|**0.0320**|**99.07%**|**0.0579**|

Mirrorはtiedを大幅に改善し、単純な同容量gainにわずかに勝つが、native gainに対する世界別BCE比は0.982,0.529,0.970と**10%以上改善した世界が1/3のみ**。pair-readoutはMirrorより約2.25倍小さいBCEで、わずか328 Bの追加に過ぎない。全体の独立MLPに対する品質・バイト共同ゲートは**0/3 FAIL**。9組すべて訓練した場合の高精度は、未学習組への汎化能力の証拠ではない。

### D：新2世界の6,000更新までの長時間追補

|方法|900更新 test BCE|2,400更新 test BCE|6,000更新 test BCE|
|---|---:|---:|---:|
|Mirror|**0.08552**|0.10562|0.12778|
|native gain|0.10092|0.12888|0.15866|
|9独立MLP|**0.03797**|0.04240|0.04845|

各セルは新2世界×2初期値の平均（各世界2seed平均の算術平均）。**全12モデルで、検証BCE最良は900更新**。テストBCEも全3方式で900更新より6,000更新の方が悪い。自然画像サンプルが少ないため、長時間学習は過学習を悪化させた。これは旧MA-247やDMFFN-001の整合教師で「長学習が改善した」という別条件の結果を否定するものではない。

## 4. C：重要な対立説明

1. **自然MLPのhidden gauge/重み整列**：別教師で学習した中間特徴は同じgate/upコード軌道に載る必要がない。Aの強い未知組BCE悪化はこれと整合。ただしB（教師を使わない直接学習）も失敗したため、**唯一の原因**とは言えない。
2. **実ラベルのAND構造がMirror SwiGLUの回転軌道と一致しない**：ラベルが3×3の論理積でも、3×3個のSwiGLU演算を共有少数Givensで表せるとは限らない。これはDMFFN-001の合成教師との主要な違い。
3. **通常headの強さ**：共有FFNの前半が十分な特徴を学び、少数のpair別出力headで強い品質に達する。Mirrorでgate/upまで変形する追加の自由度が必要ない可能性がある。
4. **BCEの不安定性**：未学習組への過度の確信による失敗が大きい。accuracyが保たれてもcalibration失敗は無視しない。
5. **過学習**：少数の自然画像サンプルで長学習すると全方式が品質悪化。更新回数を増やすだけではTransformer用MLPの容量効率を証明できない。

## 5. U：不確かさ・測定限界

- 同じ元画像コーパス1797枚の異なる層化split×初期値。3+3+3+2世界は複数独立データセットの外的再現ではない。世界単位で比較し、seedを独立の世界と数えない。n=3または2なので推論統計区間は極めて広い。
- 複数次元の相互作用を構造化して作った自然画像**タスク**であり、自然のTransformer checkpoint内部FFNを移植した実験ではない。
- 64入力、32隠れ、9二値分類のみ、言語モデリング・生成速度・KVキャッシュは評価対象外。
- 9個の出力を同時に計算する実装は単純CPU eager操作。計算速度やFLOPs Pareto優位は未測定。
- 教師は9個を本当に独立に学習したが、訓練は同一画像データ・同じバッチ列を使用した。未学習3組の教師予測を生徒最適化に渡さないことはテスト済み。

## 6. 科学的な次の関門

**次に採用すべき候補は、同じgate/up Mirrorを単純に複雑化することではなく、自然なtask間の共通部分と例外部分を選り分ける方法**である。

優先順：①native shared+pair-specific output head対MirrorのFLOPs/byte品質比較、②自然MLPのhidden-channel permutation alignmentによる教師統合、③shared gate/up＋必要なpairだけのrank1/2 private残差、④より大きい自然データでの検証と正則化・validation early stopping、⑤これらを通過してからTransformer FFN・MoEの容量自動配分。

MLPの容量コントローラは事前の検証集合で品質増分／追加シリアライズバイト／active FLOPsを見て、headだけ増やすかMirrorを増やすかprivateを追加するかを決める。**今の証拠だけで「Transformerの容量を自動最大化できる」とは言わない。**

## 8. H/T/D/C/Uの判定

- **H**: 既知9タスクへの容量圧縮は条件付きで可能。Mirrorの組み合わせ未学習転用は実用的な精度を示せず、品質同等な独立MLP代替は未達。
- **T**: 14+2+2 =18テスト、dev-frozen A/B/C/D、36+36+36+12=120生徒学習、教師3世界＋dev世界。
- **D**: Stage Aの登録されたgainだけに対する狭いゲートは2/3だがtied対照FAIL 0/3。B直接未学習組FAIL 0/3。C品質・容量共同FAIL 0/3。D長更新同品質FAIL 0/2。
- **C**: native per-pair readout、feature gauge、factorization mismatch、overconfidence、過学習。
- **U**: 同一小規模自然画像コーパス、3世界、遅いeager CPU、未比較private residual/GPU/自然言語。測定値をLLMに外挿しない。

**ERROR CHECK:** 「モデル部分の保存量86.7%削減（前処理込み85.05%）」と「同精度で圧縮」を同一視しない。3×3アドレス数は独立自由度数ではない。6組だけを学習した実験と9組すべてを学習した実験を明確に区分。旧整合教師の成功を取り消さず、自然教師/自然ラベル条件下の負例を新たに保全した。
