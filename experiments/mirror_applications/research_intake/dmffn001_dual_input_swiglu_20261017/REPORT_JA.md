# DMFFN-001 — gate×up Dual-Input Mirror SwiGLUの反復実験

**日付：2026-10-17。状態：MECHANISM / STORAGE / CPU RUNTIME、自然言語未検証。** 旧MA-251/GIC002を改変せず独立新実験。`main` と正式MA台帳は不変。

## 1. H：問いとモデル

SwiGLUは3つの大きな行列からなり、入力側の2射影にMirror Viewを配置できる。

\[
 g=xW_g,\quad u=xW_u,\quad
 y_{ij}=\left[\operatorname{SiLU}(gR_{g,i})\odot (uR_{u,j})\right]W_d.
\]

物理重み \(W_g,W_u\in\mathbb R^{8\times24}\), \(W_d\in\mathbb R^{24\times8}\)。gate側3コード×up側3コードで9論理MLPを作る。各コードは別々の2D Givens回転（最大12ペア/方向）。モデル内値は無次元。各出力は8次元。変形は**共有入力射影の後、SiLU/要素積の前**に入るため、単一入力から9出力を作る場合はgate/upの重い投影を1回ずつ共有する。各出力のdown投影と2経路のView演算は必要であり、9機能が独立になるわけではない。

主な仮説：

1. **H1** 独立したgate/upのMirrorコードを組み合わせる方式は、同じコード数のnative pair gainと、組ごとに別のMirrorコードを持つ非因子化方式より、分解可能な教師で優れる。
2. **H2** 学習していないgate×upの組み合わせでも、既存の2方向コードを再利用して汎化できる。
3. **H3** 検証誤差の停滞で回転自由度を0角から自動拡張すれば、固定12方向より少ない保存量で同等の品質を得られる。
4. **H4** 長い学習により少容量Mirrorが独立MLPの性能に接近できるが、独立関数では物理容量限界が残る。

## 2. T：事前固定した本評価

- 開発データ世界73001のみで共通学習率0.018を選択（0.008と比較、12の対応条件中11で検証MSEが低い）。**本評価5世界73111–73115は選択に使っていない。** `PRE_FRESH_LOCK.json` に学習コード・テスト・条件のSHA-256固定。
- 5独立世界×2初期値×4条件×12方式 = **480学習モデル**。各2,400 AdamW更新、バッチ64、128/512のような別設定ではなく、実際は訓練入力512、検証256、テスト512。ラベル雑音は訓練だけで真の教師RMSの3.5%。訓練入力の標準正規分布、検証・テストは別途生成。
- 条件は `aligned_full`（9組全て教師が同じ親Givens族）、`aligned_holdout`（学習6組・未知3組ID 2/3/7）、`partial_full`（9組それぞれに非分離な教師残差）、`unrelated_full`（9組独立ランダム教師）。評価NMSEは**訓練教師のRMS²**で正規化した未学習入力テストMSE。検証誤差を使った学習方法・容量制御は未学習組の情報を参照しない。
- 比較12条件：`tied`, `mirror1`, `mirror4`, `mirror12`, `gain12`, `gate_mirror12`, `up_mirror12`, `pair_mirror4`, `pair_gain4`, `factor_lora1`, `independent`, `auto_mirror`。初期共有重み・初期化seed・訓練ミニバッチ抽出は対応比較内で統一。学習曲線は300,600,1200,2400更新で保存。
- `auto_mirror` は1方向から開始し、400更新おきに**訓練済み組の検証NMSE**が前回比10%未満しか改善せず、NMSEが0.002超なら1→4→12方向へ段階拡張。新規角度はゼロ（挿入時の関数が変わらない）。検証結果を用いるため自動適応の候補であり、テストで調整していない。実保存バイトは最終有効角度だけ保存。
- 表示する一つの統計は**各世界で2シード平均し、5世界の中央値**。独立標本単位は5世界であり、10シードを10独立世界と見なさない。

独立9MLPは22,817B対Mirrorの5,081B、Mirrorは**77.7%小さい**。しかしAlignedでも2,400更新時のMirror/independentの世界対応品質比中央値**2.458**。元の事前圧縮＋品質ゲートは**0/5世界FAIL**。保存量が小さいだけでは高品質圧縮の完全成功にはならない。

### 3.3 自動容量拡張

`auto_mirror` はAligned-fullの10試行中9件が最終12方向・1件が4方向。固定mirror12より世界中央値MSE約**2倍**（0.097616対0.048528）。保存量が小さくかつ品質差が10%以内という事前ゲートを満たす世界は**0/5**。関数保存の拡張自体はテストで保証されたが、単純な検証停滞ルールでは容量を十分うまく配分できない。**自動的にTransformer全体の容量を最大化できるという段階ではない。**

### 3.4 実学習時間と推論コスト

解析上、大きな行列積MACだけ数えると、9個の独立MLPは1入力につき \(9\cdot3dh=5,184\) MAC。共有gate/up入力射影＋9つのdown射影は \((2+9)dh=2,112\) MAC。ただしGivens変換・SiLU・要素積・メモリ移動は省略される。

実CPU・非融合PyTorch・1スレッド・batch64で、**9論理出力をまとめて計算**した中央値はMirror12 **0.1644 ms**、同byte gain12 **0.1358 ms**、独立9MLP **0.0814 ms**。すなわち**理論MACの削減は現実の速度改善になっていない**。加えてmirror12/independentの訓練経過時間比は本評価世界中央値約1.37。Givens逐次演算やPython/Eagerの支配・微小行列などがあり、カーネル融合の優位は未検証。

## 6. C：反証・失敗境界と次段階

1. **適合教師バイアス**：教師のAligned生成則は研究対象のMirror12と厳密に一致し、Mirror有利。低bit数が大規模な自然言語データを圧縮できるという一般結論ではない。Unrelatedでは強いFAIL。
2. **学習予算**：固定2,400/6,000更新はクラス最適性の証拠でない。もっと長期の学習や最適化・ミニバッチ/データ数の独立対照が必要。
3. **容量分配失敗**：単純な自動成長は0/5で失敗。真に自動配分するなら複数ブロック間で「検証誤差の減少 / 追加バイト / 追加学習FLOPs」を予算制約で比較するcontrollerを別の新世界で検証する。
4. **単側アブレーションの課金**：gate/up片側方式は使わない座標のパラメータも確保・保存しているためバイト比較には使用不可。修正した公平な単側制御は新しい改訂プロトコルで再実験が必要。
5. **速度**：行列積の理論上の削減よりCPU Eager Givens実装オーバーヘッドが支配しており、現時点で推論高速化はFAIL。MLPの9論理出力は同じ入力を共有しているが、通常の連続したTransformer層では入力状態が変化するため、周回間で前半の射影をそのまま再利用できない。
6. **Transformerは未評価**：Attention、残差、正規化、RoPE/KVキャッシュ、実言語NLL、GPU/Triton fused kernelは今回一切計測していない。FFN Viewの配置で後続AttentionのKVが変わる場合、既存キャッシュは自動で有効にならない。

**結論（D）**：gate×upの因子化Mirrorは、適合する非線形教師で**同じ648パラメータ/5,081Bのnativeゲートとpair専用Mirrorを上回る有効な組み合わせ再利用機構**。未学習の3組でも再利用性が確認された。ただし、独立9MLPに匹敵する精度、無関係なタスクへの転用、更新数による完全な学習の補償、**動的自動容量割当て、実推論高速化**は未確立または否定的。今はMLPの構成機構を確認した段階であり、Transformer全体の容量最適化が自動的に実現したわけではない。
