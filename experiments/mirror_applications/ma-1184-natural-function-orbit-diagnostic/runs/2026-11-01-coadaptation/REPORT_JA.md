# MA-1184：共有核とMirrorコードの共同学習 — L0/L1開発実験

**2026-11-01 JST / 開発実験完了 / 共同学習の改善：各課題5/5 / Mirror固有の優位：各課題0/5**

これは新しい課題族での独立L2確認ではありません。全結果は開発用の教師関数に対する診断です。Mirror整合な教師は用いず、解析関数を独立に学習した通常MLPを教師にしました。過去の実験判定やmainは変更していません。

## 1. 何を実行したか

- 本比較：3課題族×5課題世界。Mirror/FiLM/結合rank1×2初期コード×4学習条件で360構成。そのうち90は無学習A、270は学習B/C/D。共有および独立MLPの参照60構成を加え、合計420構成、330学生訓練。
- 教師は各世界でsource1＋target3の独立MLP、計60訓練。source関数の出力だけを使って共有核を15回事前学習。教師重みや生成係数を学生へ渡していない。
- 別パイロット48構成（39学生訓練＋9無学習）、教師12、共有核3。主比較と混ぜない。再現検証の2件の再訓練も新規科学的試行として数えない。
- 入力8・共有隠れ16・出力3・3タスク、ReLU。外部task IDは全方式に同一に与え、入力からtaskを推定するrouterは未実装。Loop/MoE/Privateは導入していない。
- A：両方固定、B：コードだけ学習、C：核だけ学習、D：両方学習。各方式・世界・初期コード内では初期全パラメータが厳密に一致。コード2初期値はSELECT DEVだけで選択し、独立標本数は各課題5世界のまま。

## 2. データと実装前提

教師は8→32→3の普通のReLU MLPを4096 train/1024 DEV、1000更新、batch128で訓練。共有核はsource教師から1024 train/256 DEV、400更新で蒸留。学生は各タスク768 train/256 SELECT DEV、500更新、batch128、AdamW lr0.006/weight_decay1e-4/clip1。SELECT DEVでcheckpointとrestartを選択。全checkpointをSHA256封印してから各タスク512例の新しい入力auditを生成しました。これは同じ開発タスクの未使用入力であり、新規タスク族Fresh/OODではありません。

NMSEは各タスク・各出力のMSEをそのタスクのTRAIN出力分散で除し、出力とタスクを平均した無次元値。評価側の分散で再正規化していません。教師自体の解析関数への誤差も別途保存。操作変更族では教師近似誤差が他より大きいため、学生が教師を再現する成績と元の解析演算の厳密な学習は別です。

**推論:** 学習済みコードは、元の核へそのまま移すだけでは同じ機能を発揮しません。核とコードの組合せへの依存を示します。ただし、この介入は入力状態の分布を変えるため、独立した「意味モジュール」を発見した証明ではありません。FiLM・結合rank1にも同種の劣化があり、Mirror固有の協調性とも言えません。

コードを別タスクへ切り替えたとき、切替先の教師出力への誤差が改善する指標も測定しました。Mirror/FiLM/結合rank1のすべてで改善が見られます。単なるコード破壊による悪化だけをもって意味的な機能移管と解釈しません。

## 6. パイロットと初期化監査

別パイロット3課題すべてが凍結済み事前ゲートを通過。本比較15世界でも、教師max DEV NMSE<0.20、独立幅32 DEV<0.30、能力のある非Mirror対照DEV NMSEが0.005～0.30、有限・非ゼロのMirrorコード勾配を確認しました。過去の極小誤差に対する達成不能な絶対改善ゲートは使っていません。

初期化変化は実際の入力で測定し、無理に約1%へ揃えていません。MirrorとFiLMの初期関数は異なります。Mirrorと結合rank1は同一初期関数です。これは四条件内の因果比較には問題ありませんが、方式間の性能差から初期化以外の構造効果だけを識別したとは言えません。

## 9. H/T/D/C/Uと次の判断

**H:** 共有核とコードの共同学習が片側だけの学習より有効で、さらにMirrorが非Mirror対照より有利か。
**T:** 開発5世界×3課題、2コード初期値、4学習条件、3条件付け方式＋4参照。監査入力はcheckpoint封印後に生成。
**D:** 共同学習ゲート各5/5（開発信号あり）、Mirror固有ゲート各0/5（不通過）。L2確認は未実施。全体を確証PASSへ昇格しない。
**C:** 改善は一般的な条件付き共同学習、追加の可学習係数、帰納バイアスや初期化に由来する可能性。演算変更族では独立MLPの方が有利であり、無関連機能の共有には限界。
**U:** 課題族3、世界seed5、全てReLU学生、source核の作り方、2初期コード、500更新の未収束、独立対照へのsource情報不均衡、CPU非固定クロック。誤差の不確かさと数値再現性は別物。

**次の推奨:** 「核を固定してMirrorコードだけを学習」を主な検証経路にするのは、この結果では不適切。共同学習を保った上で、FiLMにも出る共通の改善と、Mirrorによる境界変更の独自効果を分ける。自動的にPrivate/Loop/MoEを追加せず、学習後の活性化境界とタスク差の対応を先に調べる。固定核の失敗はMirror一般の不可能性ではないが、共同学習の改善もMirror固有の優位ではない。
