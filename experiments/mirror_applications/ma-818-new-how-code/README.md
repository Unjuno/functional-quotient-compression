# MA-818 — add a new how/mechanism

## H / T / D / C / U

**H:** A new operator code on a frozen shared operator basis preserves behavior on known content and beats explicit new-operator storage with lower full state.

**T:** Synthetic 8D linear mechanism basis, six fixed content vectors, four known hows, one additional how fitted from 32 support input-output examples; seed 81801; zero optimizer updates. Compared independent operator bank, explicit new operator, Mirror code and native operator-coordinate code.

**D: FAIL.** Mirror reaches zero heldout output error and uses 1,603 B versus 2,088 B explicit new-operator bundle (23.2% fewer), but misses the frozen 25% threshold. Native operator coordinate code also reaches zero error and is 1,611 B. The 8 B Mirror difference is serialization layout only. The whole independent bank is 1,867 B.

**C:** Ordinary basis-coordinate fitting explains the result; the Mirror code does not exceed the native operator coordinate method. The modest savings miss the preregistered threshold.

**U:** Learned operator bases, multiple new hows, natural reasoning/continual tasks and fresh seeds. Fresh remained sealed.

## Evidence separation

- **Fact:** Full payload sizes, hashes, heldout errors, retention and replay are in `RESULTS_CORE.csv`.
- **Interpretation:** A new operator is addressable in the synthetic frozen basis, but no Mirror-specific improvement or threshold-level compression was established.
- **Hypothesis:** Multiple operator additions may amortize basis state, which this one-operator screen does not test.
