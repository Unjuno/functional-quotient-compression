# MA-181 — block-circulant Mirror

## Prior-art search

The targeted search found direct structured-weight controls. Block Circulant Adapter (BCA; arXiv:2505.00582) stores block-circulant adapter weights and reports large parameter/FLOP reductions against PEFT baselines, while discussing a training heuristic to avoid divergence. Compact Circulant Layers with Spectral Priors (arXiv:2602.21965) parameterizes real-FFT spectra for circulant and BCCB layers, including Hermitian constraints and spectral priors. Generalized structured-matrix learning (arXiv:2310.18882) learns structured weight patterns and compares against low-rank and block-sparse alternatives. These works establish block-circulant compression as prior art. The narrower question here is whether one paid block kernel bank plus small role shift tables can serve multiple logical functions. Therefore independent BCA-style block-circulant matrices and dense matrices are both required controls.

PA11 requires MAP/sign-permute and Hadamard binding controls; PA12 establishes circular convolution as a known binding operation. Those controls test whether block shifts offer a useful logical address beyond known shared transforms.

## H — falsifiable hypothesis

A shared block-circulant kernel bank plus per-role shift indices can reproduce four roles generated by those same shifts, within 1.10× untied held-out MSE and at no more than 0.65× untied actual bytes. Independent block-circulant adapters indicate whether block structure alone explains the effect.

## T — frozen protocol

Four roles each map 16 input dimensions to 16 outputs. Each 16×16 role map consists of 16 circulant blocks of width four. The candidate uses one shared bank of 64 kernel values; each role has 16 integer shifts in {0,1,2,3}. All shift indices, weights, and metadata are stored in the serialized payload. The teacher uses the same block-circulant shift family; independent roles use arbitrary dense matrices.

Controls: untied dense, independent block-circulant, hard-tied block-circulant, MAP, Hadamard, fixed HRR, learned Givens, and dense shared plus rank-1 residual. Development compares learning rates 0.003 and 0.01 on seeds 18101–18102; one common rate is selected using mean held-out MSE across all methods and both conditions. Fresh seeds 18111–18113 remain sealed unless both development worlds pass. Training uses 1,200 AdamW updates, batch size 64, matched inputs, one CPU thread. Metrics include held-out MSE/R², actual serialized bytes, optimizer updates/examples, MAC proxy, wall time, and inference throughput.

The MAC proxy models FFT-based block circulant multiplication; the small eager harness materializes dense matrices for its actual runtime measurement. No language-model, near-convergence, or capacity claim follows from this screen.

## D — PROMISING storage/quality frontier; runtime regressed sharply

### Fact

- Development selected common learning rate 0.01 by mean MSE across all methods and conditions: 1.1113332 versus 1.1113512 at 0.003. Both development aligned worlds passed the candidate's quality and byte gates.
- Fresh block-shift Mirror held-out MSE on seeds 18111–18113 was **8.35e-11, 7.87e-11, 1.25e-10**, versus untied 1.36e-10, 1.48e-10, 2.20e-10. It passed the <=1.10× MSE gate 3/3.
- Block-shift payload was **2,657 bytes** versus **6,437 bytes** untied (0.413×; 58.7% fewer), with all 64 per-role shift indices serialized. The independent block-circulant adapter control was 3,365 bytes (0.523×); it averaged MSE 1.08e-10 versus 9.58e-11 for block-shift Mirror. Thus the address-shared form saves 21.0% bytes against this strong BCA-style control while retaining similar quality.
- Hard-tied block-circulant used 2,405 bytes but had MSE around 1.13. MAP, Hadamard and fixed HRR versions used 6,689 bytes and MSE around 1.56–1.93. Givens and shared dense plus rank-1 residual also failed to approach the shift teacher (mean MSE 0.984 and 0.717, respectively).
- On arbitrary independent role matrices, block-shift Mirror averaged MSE 1.77; the untied upper control averaged 1.62e-10. Private independent BCA also failed (mean MSE 1.47), so this boundary requires dense private parameters rather than only a block-circulant representation.
- The MAC proxy for block-shift was 83.56M versus 78.64M untied. Measured mean training wall was 9.34 s versus 0.92 s, and median CPU inference throughput was about 33k vs 1.40M examples/s. Independent block-circulant was similarly slow. The harness materializes dense matrices through Python loops, so these measured timings are implementation-specific; no compute or runtime advantage is claimed.
- Each method used 1,200 updates and 76,800 examples per trained model. No near-convergence or fixed-byte capacity analysis was run.

### Interpretation

One block kernel bank plus charged role shifts improves the actual-byte/quality point over independent block-circulant adapters on a teacher generated by those same shifts. The gain appears to come from sharing repeated physical block kernels across logical roles, not from a better approximation than BCA. It trades extra address state and expensive current reconstruction for lower bytes; runtime did not improve. Arbitrary functions require private dense state.

### Hypothesis

The role shift tables identify which circulant version of each block to use, so one stored bank replaces repeated kernels when roles share this exact orbit. The poor independent-mode results suggest block structure and shared addresses both break when the role matrices are unrelated.

### C — strongest counter-hypothesis

The teacher was generated by the exact block-shift family tested. Independent BCA already gave nearly identical quality at only 708 additional bytes. The large wall-time/inference regression is also real in the present implementation; an FFT kernel may reduce arithmetic but has not been implemented or benchmarked here.

### U — not established

Optimized FFT execution, larger blocks/shapes, learned or unknown shift codes, natural activations, nonlinear experts, language quality, convergence-matched BCA controls, and fixed-byte frontiers remain untested.

### Fact / interpretation / hypothesis

- **Fact:** block-shift Mirror passed the registered aligned quality/byte gate in 3/3 fresh worlds, used 0.413× untied bytes, and was 21% smaller than independent block-circulant. Measured runtime was much slower.
- **Interpretation:** block shifts can reuse physical block kernels across roles sharing the shift family, with a storage win and substantial eager-runtime cost.
- **Hypothesis:** an optimized FFT-based implementation may recover some runtime, but would need an independent block-circulant comparison and must still account for all address bytes.
