## H — hypothesis

A shared translator basis plus small per-expert Mirror codes and a private fallback can reproduce a routed Mixture-of-Translators target trajectory with lower serialized bytes than full MoT translators, while retaining PA238's router and target context correction.

## Mirror insertion

> **Mirror insertion:** this experiment adds a per-expert code m_e to the translator matrix interface so that several logical translator experts are reconstructed from one shared translator basis without storing each full translator matrix.

The physical objects are translator expert matrices. The router and target context correction are native MoT components and remain present in every primary method. `m_e` is static per logical expert and every code, matrix basis, router and correction map is serialized and charged. Angles are supplied by the synthetic teacher, not learned from calibration data.

## Prior-art delta

PA238's MoT uses a router over translators and a target-side context correction to reduce trajectory drift. This screen retains both. Its synthetic sequence task isolates whether the translator bank itself can be compressed by an expert-view basis. Five aligned experts are generated by eight per-expert output Givens angles over one full-rank shared translator; a sixth unrelated expert requires private storage. A conventional shared matrix-bank control and per-expert low-rank residual control are also tested. Native full MoT, independent low-rank translators, an ordinary shared matrix-bank control, and Mirror codes are compared. The ordinary shared matrix bank is the nearest non-Mirror control and may be algebraically equivalent.

## Trial

Synthetic CPU trajectory translation: hidden width 16, 6 translator experts, top-2 soft routing from the shared router, 8 recurrent translation steps, 4-D target context correction at every step, 5 aligned experts and 1 unrelated private expert. Development worlds 88101–88102 choose shared-bank rank from {1,2,3,4,5} and independent residual rank from {1,2,4,8}. Fresh worlds 88111–88113 are sealed until source/config freeze. No optimizer updates or real model-pair calibration are used. Metrics are normalized target-trajectory MSE, payload bytes, per-step MAC proxy, and measured CPU wall time.

## Gates

PASS requires all three fresh worlds to have trajectory MSE <=1e-4, at least 20% fewer serialized bytes than native full MoT, <=1.25x native MoT MACs, and >=10% fewer bytes than the ordinary shared matrix-bank control at matched quality.

FAIL if a gate is missed or the ordinary shared matrix-bank control matches Mirror quality/bytes within 10%. A mechanism pass would not establish cross-model KV transfer or target-model quality.

## Fact / Interpretation / Hypothesis

FACT: On 3/3 fresh seeds the Mirror trajectory MSE was 1.04e-15–1.23e-15; its serialized payload was 3,201 B versus 7,039 B for native full MoT (54.5% fewer) and 7,274 B for the exact rank-4 matrix-bank control (56.0% fewer). Mirror translator MAC proxy averaged 263,680 vs native 393,216, but mean CPU wall time was 51.1 ms vs 36.4 ms. A post-fresh accounting amendment measured setup factorization cost separately: the shared-bank SVD used an estimated 26,600 FLOPs and independent rank-16 fitting 245,760; Mirror angle extraction was supplied and unmeasured.
INTERPRETATION: For this deliberately aligned translator family, structured Views improve the storage/translator-MAC frontier and a private expert handles the unrelated boundary; the unoptimized Givens path is slower in measured CPU wall time.
HYPOTHESIS: Some real translator banks may admit compact functional coordinates, but the result does not establish cross-model cache translation quality.
BOUNDARY: Synthetic routed recurrent vector translation only. The additive context map is a proxy for target-context correction; no MoT correction loss or real LLM handoff was implemented.
