# MA-468 — Polytropon shared/private skill bank with Mirror skill views

Status: **NOT ESTABLISHED** (development screen; fresh seeds sealed)  
Evidence lane: MECHANISM/STORAGE/QUALITY/COMPUTE  
Branch: `research/ma-468-polytropon-mirror-skill-views-20261008`  
Base commit: `595a429`  
Prior art: PA85 (Polytropon)

## H — Hypothesis

Three physical shared skills, each expanded into two logical functions by a compact rank-one View, plus four private skills for unrelated functions could represent sparse task compositions with low error and fewer actual bytes than an explicit ten-skill Polytropon bank. A direct low-rank view control tests whether any effect is Mirror-specific.

## T — What ran

The frozen 8D task has 10 logical skills: six aligned skills generated by three physical matrices plus a shared rank-one direction, and four independent private skills. Twelve task functions use a serialized sparse allocation table: eight combine two aligned skills; four select a private skill. Each task has 128 support and 256 query vectors with noise σ=0.015. All methods received 4,000 Adam updates × 32 sampled examples. Development seeds were 46801 and 46802; fresh seeds 46811–46813 stayed sealed. Controls were an explicit ten-skill bank, three shared skills without Views plus four private matrices, a direct native shared-basis low-rank map, and independent full matrices per task.

Actual `.npz` payloads include all physical and private matrices, View basis/codes, task-skill indices and metadata. The fixed task allocation is paid; this is a skill-bank screen, not a learned-router reproduction.

Mirror reduced the named skill-module count from ten to seven and had lower fixed-update RMSE than the explicit skill bank in both seeds. But its actual payload was 4,045 bytes, 11.2% larger than Polytropon's 3,637 bytes; it also took longer to train. The physical-only model had fewer bytes but could not represent aligned view variation. The independent task upper control exceeded the preregistered 0.025 RMSE validity bound in both seeds, indicating that the frozen fixed-update task may not establish the unrestricted quality frontier. The direct native low-rank control matched Mirror payload hash and per-task outputs exactly. Metric replay and byte checks passed; full per-task values are in `RESULTS_CORE.csv` and `runs/dev_*`.

The quality difference is a fixed-update learning-efficiency signal only. The independent upper control was not near-converged, so these results do not establish capacity. The Mirror payload is also not a storage win on actual serialized bytes.

## D — Decision

**NOT ESTABLISHED.** The protocol explicitly requires the independent task upper control to reach mean query RMSE <=0.025 in both seeds; it reached 0.04144 and 0.03550. Fresh worlds therefore remain sealed. Separately, Mirror fails the byte gate and is exactly reproduced by native low-rank skill views. The fixed-update quality signal supports further diagnosis but not a capacity, storage, or Mirror-specific claim.

## C — Strongest counter-hypothesis

Ordinary shared-basis low-rank task adaptation explains all Mirror outputs and module-count reduction. Additional array headers, code, indices and private state erase storage savings; the explicit skill and independent controls may simply need more optimization to reach their frontier.

## U — Unconfirmed

Near-converged independent quality, actual storage Pareto frontier, learned Polytropon allocation, natural task transfer, and whether better serialization or a stronger non-aliased coordinate changes the result remain untested. No fresh data was opened.
