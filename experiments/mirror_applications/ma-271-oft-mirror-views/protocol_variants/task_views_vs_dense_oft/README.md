# MA-271 — OFT Mirror task views

Status: SCREENING (protocol frozen)
Evidence lane: MECHANISM / STORAGE / RUNTIME
Base commit: `f7f76de193063950d28b7834f337840b1e86f0ce`
Prior art: PA20 Orthogonal Fine-Tuning (OFT).

## H — falsifiable hypothesis

On a task family generated by orthogonal transforms of one shared map, compact Mirror task coordinates will preserve quality while reducing actual transform bytes relative to native full orthogonal task transforms, and beat byte-near simple block-orthogonal or low-rank controls.

## Mirror insertion

> **Mirror insertion:** this experiment adds a small task address `m_t` to the shared pretrained linear map's output geometry, selecting a structured orthogonal realization without storing a dense independent transform per task.

- Shared object: one 16x16 physical map.
- Native OFT: learned dense orthogonal matrix per task via skew-symmetric Cayley map.
- Controls: independent task matrices; native OFT; rank-2 task residual.
- Mirror: eight-parameter product of fixed adjacent-plane Givens rotations per task.

## Protocol

Four tasks, 16D inputs/outputs, 1,000 AdamW updates, batch 128. Teacher is one shared map followed by task-specific orthogonal output rotations. Development worlds 27100/27101, LR {.003,.01}; fresh 27102–27104 sealed unless dev promising. Measure held-out MSE, actual bytes and active transform MAC proxy.

**PASS (screen only):** Mirror MSE <=1.10x independent, payload <=60% independent and >=10% better MSE than native OFT at byte-near cost (within 15%) or lower bytes. **FAIL:** gate missed or OFT/simple control matches at equal/lower bytes.

## Boundaries

Synthetic linear orthogonal family; no natural-language or general capacity claim. Eager transform runtime is reported, not generalized to optimized kernels.

### Serialization correction amendment

Before any fresh access, audit found that dense realized Mirror matrices were serialized instead of the exact compact angle coordinates. Protocol amended: Mirror now serializes the eight learned angles, sufficient to reconstruct its matrix-free inference transform; native OFT is charged its dense effective task matrices. The first dev rows are superseded for storage and retained in the git history; all development methods are rerun. The duplicate block-orthogonal arm was removed because it was the same adjacent-plane parameterization as Mirror.

## D — PROMISING (Givens-aligned synthetic family)

Development selected LR 0.01. On all three fresh worlds, Mirror MSE was 4.4e-10–8.2e-10; independent full maps were 2.7e-11–3.1e-10. Native OFT MSE ranged from 9.6e-7 to 2.9e-3 under this fixed-budget implementation, and rank-2 residual MSE was 0.125–0.210. Mirror serialized payload was 3,309 B versus 7,253 B for native dense OFT and 7,261 B independent (54.4% fewer bytes than OFT). It passed the predeclared quality/storage gate in 3/3 fresh worlds.

Compute/runtime differ: Mirror's active MAC proxy was 69.6M versus 2.16B for dense OFT and 196.6M independent, but measured eager CPU throughput was only 0.19–0.21M examples/s because the Givens transforms use Python loops. Thus the compact transform has a low arithmetic proxy but poor unoptimized implementation latency. No serving-speed claim is made.

### C — strongest counter-hypothesis

The teacher is deliberately generated from the same eight-plane Givens family as Mirror, so exact recovery and compact storage are expected on this aligned case. Native OFT's dense Cayley parameterization is not a full paper-level OFT reproduction or a tuned optimizer; its fixed-update results may understate native OFT.

### U — not established

Arbitrary task orthogonal transforms, natural language, optimized GPU/fused runtime, near-convergence fixed-byte capacity, and unseen task-code generalization are untested.

### Fact / interpretation / hypothesis

- **Fact:** Mirror passed quality/storage gates in all 3 fresh worlds at fixed LR=0.01; its serialized state contains the shared matrix and 32 Givens angles, not dense task matrices.
- **Interpretation:** When task differences lie in the tested compact rotation family, Mirror can replace dense orthogonal per-task transforms and reduce payload substantially. The current implementation has severe CPU latency overhead.
- **Hypothesis:** A fused Givens kernel may retain the storage/quality result while closing the runtime gap; arbitrary rotations may need more angles/private state.
