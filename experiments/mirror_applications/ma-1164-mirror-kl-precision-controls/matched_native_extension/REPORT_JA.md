# MA-1164 追加監査：物理パラメータ数を揃えた通常MLPとMirror生成MLPの比較

## 1. 研究目的と立場

この研究は既存のMA-1164（Mirror K×反復R）に対する、**事後登録した追加対照**である。前段の成績を見てから比較条件を追加したため、前段研究と一体の事前登録成功とは扱わない。今回の学習率は開発用分割618440/618441のみで選択し、未使用分割618450/618451/618452を各2初期値で固定評価した。

**Mirror insertion:** 元の通常MLP（64→16 tanh→10）の1210係数を、m個の物理係数と固定K方向Mirror＋tanh＋R段残差再帰による仮想重みに置換する。比較対象は、幅を調整して学習係数をmに近づけた通常MLP、非Mirror疎直交生成、FP16保存の通常MLP。

### 最も重要な非対称性

Mirrorは**まず通常の幅16・1210パラメータNNを教師ラベルで学習し、その学習済み重みだけを用いて機械的に変換**している。一方、小型通常MLPは初めから教師ラベルだけで学習する。これは変換済みMirrorの直接学習性能や、少ない学習コストでの学習可能性を比較したものではない。全教師の900更新をMirrorの全体訓練コストに含めなければならない。

## 2. 実装と固定条件

- データ：`sklearn.datasets.load_digits`、8×8画像1,797枚、10クラス。各世界で80%作業データ/20%テスト、その作業データを訓練/開発に層化分割する。同じ全データを別の乱数で分割しているだけで、**独立した自然ドメインを3つ集めたわけではない**。
- 通常MLP：入力64、隠れ幅6/7/10/11/13/16、出力10、隠れtanh。独立学習スカラー数は460/535/760/835/985/1210。AdamW、weight_decay=0、最大900更新、batch128、gradient clip1.0。
- 開発LR候補：0.004、0.008、0.016。開発選択LRは幅6/7/10/11/13/16の順に0.004/0.008/0.008/0.016/0.008/0.008。freshを見て調整なし。
- Mirror：m=256/512/768/1024、固定(K,R)=(2,4)/(2,4)/(8,4)/(2,4)。Kの並列方向は固定のGivens＋Householder＋置換、活性化tanh、残差係数0.16。重みだけを入力とする逆展開とL-BFGSでフィット。
- 非Mirror：同じ固定直交基底と同じm個の選択座標を使うが、K方向非線形Mirror反復なし。
- 実行環境：PyTorch 2.10.0+cpu、AMD EPYC 9V74仮想CPU（可視5 vCPU）、CPU 1スレッド、FP64 eager演算、CUDAなし。FP16は**保存重みを16bitにした後、推論時にFP64へ変換**した結果であり、FP16 GPU演算ベンチマークではない。
- 完走：固定fresh3分割×seed51/52×20モデル条件=120行、実測serialized bytes、batch64推論時間中央値、NLLと正解率。source SHAを検証記録に格納。

このpayloadはPython `torch.save` の**実バイト数**であり、さらに必要となる共通/専用Mirror実行プログラムのソースや最適化器の状態を含めていない。従って上記のMirror容量比較は、Mirrorに有利な下界である。

同パラメータ近傍では、m512に対して幅6（460係数）より-1.620ポイント、m768に対して幅10（760係数）より-0.648ポイント、m1024に対して幅13（985係数）より-0.093ポイントの差。m768対幅10の差は3世界とも負（-0.556/-0.417/-0.972ポイント）。FP16通常NNのほうが小容量で高精度である。

Mirrorが非Mirror疎直交生成に勝った平均値はm512で+0.694ポイント、m768で+0.185ポイント。しかしm768では事前ゲート「各世界で+1.0ポイント」を3世界とも満たさず、m1024は-0.093ポイント。Mirror固有の実用的改善を支持しない。

### 訓練の公正性

通常幅6/10/13の900更新の実学習時間中央値は0.480/0.465/0.457秒。Mirrorの場合、幅16教師NNの900更新が中央値0.496秒、**それに**重みコンパイルのL-BFGS時間がm512/768/1024で0.046/0.142/0.045秒加算される。CPU混雑・クロック固定なしであるためこの差をハードウェア上の普遍的速度比とはみなさない。

## 4. プロトコル整合性の事故と訂正

最初の実験拡張の`PROTOCOL.json`はfresh世界618450/618451/618452を固定していた。しかし先に存在した実行ソースの`FRESH_WORLDS`値が618460/618461/618462となっていた。さらに旧実装は幅16の通常NN再利用時に属性`.h`が存在せず例外停止した。

1. 幅16モデルを損失なく同型の`NativeWidth(16)`へコピーする修正を行い、単体テストで出力が厳密に一致することを確認。
2. 別の618460/461/462で完了した実行は**プロトコル指定外の探索扱い**とし、成功ゲートや結果表には一切採用しない。
3. 未変更の開発選択・K/R・LR・更新数を使い、記録済みプロトコルの618450/451/452で再実行。元の結果は削除せず独立フォルダに保存。検証時に9件の単体テストがPASS。

この順序と逸脱を隠さない。開発/試験データの一般的な独立性を意味するものでもない。

## 5. H / T / D / C / U

**H（反証可能仮説）**：同等の物理係数数・保存量の通常MLPより、Mirrorの仮想幅16構造は手書き数字分類で少なくとも+1ポイント高い精度を示し、同m非Mirror生成を少なくとも+1ポイント超え、かつ総保存バイトでFP16通常NNより小さくできる。

**T（最小検証）**：幅可変MLP6/7/10/11/13/16、物理m256/512/768/1024、開発2分割で通常LRのみ選択、fresh3分割×2シードの全120条件。新規freshの途中停止なし。

**D（合否）**：m768対760係数通常NNの+1ポイントゲート0/3 FAIL、対同m非Mirrorの+1ポイントゲート0/3 FAIL、FP16通常NNに対する保存量ゲートFAIL。Hはこの条件でFAIL（Mirror-native全体の一般的否定ではない）。

**C（破れ方）**：通常の小型MLPでも多数クラスを分類でき、通常FP16保存で品質を損なわない。Mirrorは独立方向を増やさず、重みの教師依存変換、追加の反復演算、保存索引を必要とする。

**U（不確かさ）**：同一データ源の再分割、CPUのみ、精度64bit、学習済み教師ありコンパイルとネイティブ学習の非対称性、固定Mirror族。測定時間の合成標準不確かさ`u_c`と包含係数`k`は校正なしのため未推定。6seedを6独立ドメインと解釈しない。

## 6. 次段階

Mirrorへの公平な直接学習、容量制約付きの座標方向最適化、非Mirror同容量対照との複数ドメイン比較が必要。関連する分野：**情報理論**（索引と生成器の実符号長）、**数値線形代数・群論**（可逆変換と方向のゲージ）、**最適化理論**（教師重みからの変換対直接学習）、**GPUシステム**（転送量と生成レイテンシの分離）。
