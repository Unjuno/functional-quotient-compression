# MA-1037 post-development retrieval timing correction

After train-qrels selection was completed, code review showed that the initial throughput timer measured score-matrix multiplication but omitted exact top-10 selection. Before opening test qrels, timing was corrected to include matrix scoring, top-10 selection, and ordering. The dev selection was replayed and all five selected angles and all 84 development grid scores were byte-identical. No model, split, dimension, coordinate, metric quality rule, or gate changed. The original dev output is retained as `runs/DEV_SELECTION_BEFORE_TIMING_FIX.json`; `runs/DEV_SELECTION.json` is authoritative and its selected angles are frozen in `DEV_LOCK.json`.

A final pre-audit payload review found the matched linear boundary control serializes the exact same candidate vectors as Givens (asserted bit-exact in the runner). To avoid storing a duplicate copy in the artifact bundle, both control manifests reference the same candidate `.npy` file. The control's 8-byte coefficients and metadata remain separately charged; its candidate table is charged in its per-method complete payload. This is byte-accounting deduplication only. Development angles and scores remain unchanged and audit is still unopened.

The full-dimensional (768-D) zero-view candidate is also an exact alias of the paid source embedding table. Before audit, its manifest was changed to reference that table instead of writing a duplicate `.npy` file; the source bytes are charged once. The dev angle/grid replay remained identical. This deterministic full-dimension deduplication applies equally to native, Mirror, and linear-control arms.
