# MA-511 — Hierarchical condition × behavior Mirror codes

Status: FROZEN_SCREENING  
Evidence lane: MECHANISM / STORAGE / HELD-OUT COMPOSITION  
Base commit: `25c4f935`  
Prior art: PA101 (Conditional Activation Steering)

## Hypothesis

H: A condition-specific Mirror View composed with a shared behavior code predicts held-out condition-behavior interventions with lower bytes than storing a separate intervention for every pair, while matching generic full-matrix layer factorization.

## Mirror insertion

> **Mirror insertion:** this experiment adds a condition coordinate `m_c` as a Givens View over a per-behavior rank-4 code, so an unseen condition×behavior combination can be expressed without storing its pair-specific activation vector.

- Shared object: fixed 64×4 activation basis plus one code per behavior.
- View: two Givens angles per condition.
- Logical objects: 12 conditions × 10 behaviors; hold out 20% of pairs while each condition and behavior remains represented in training.
- Controls: explicit pair table, hard behavior tying, diagonal factorization, generic full 4×4 condition matrix × behavior code.

## Frozen protocol

- D=64, rank=4, C=12, B=10.
- Target coefficient function: `c[c,b]=R(theta_c) z_b`; `rho=.1` adds coefficient-space private residual.
- Development worlds 51100/51101 × seeds 0/1/2; choose common Adam steps from {400,800} based on Mirror held-out NRMSE.
- Fresh worlds 51120/51121/51122 × seeds 0/1/2. Fresh settings are locked before evaluation.
- Train all factorized models only on observed pairs; evaluate all held-out combinations. The explicit pair table is an oracle storage upper control, clearly labeled.

## Gates

- PASS at `rho=0` if every fresh world has held-out NRMSE ≤0.05, Mirror bytes ≤80% of the explicit pair table, and Mirror lies on a better quality/byte point than generic full condition matrices.
- PROMISING if pair-table compression and held-out quality pass but generic factorization matches Mirror or runtime is worse.
- FAIL if held-out quality/bytes fail or simpler factorization dominates.
- Report actual torch-serialized bytes, held-out/observed NRMSE, optimizer updates, MAC proxy and decode latency.

## Boundaries

Synthetic Givens-aligned condition/behavior functions only. No pretrained LM, natural behavior composition or independent-capacity claim. `rho=.1` maps the off-orbit/private boundary.

## Results

### H / T / D / C / U

**H:** A per-condition Givens View composed with per-behavior codes recovers held-out condition-behavior interventions more compactly than a pair table and generic condition matrices.

**T:** Synthetic 12-condition × 10-behavior bank, rank-4 shared 64D basis, 20% held-out pairs; aligned `rho=0` and off-orbit `rho=.1`; three fresh worlds × three seeds; common 800 Adam steps selected on development. Controls: exact pair coefficient table, shared behavior tying, diagonal factorization, generic full condition matrix, Mirror Givens.

**D: PROMISING, synthetic aligned composition only.** At `rho=0`, Mirror held-out NRMSE mean was 9e-6 (max 7.9e-5) at 3,297B. The exact pair table used 4,773B; generic full condition matrices used 4,001B with mean error 2.8e-5. Mirror is 30.9% smaller than pair table and 17.6% smaller than generic matrices at comparable quality. Its measured CPU decode was 0.063 ms/bank vs 0.021 ms generic (~3× slower). At `rho=.1`, Mirror NRMSE rose to .216; generic full matrices reached .323; pair table remained exact. Simple tying/diagonal controls were poor on aligned held-out pairs.

**C:** The target is generated by the same Givens View family. Generic full matrices also recover it nearly exactly; the byte improvement is representation-specific but runtime regresses in the unfused CPU implementation.

**U:** Natural CAST conditions, pretrained LM interventions, real behavior composition, larger banks, and optimized GPU decode are untested.

### Facts

- 90 fresh rows: 2 residual regimes × 3 worlds × 3 seeds × 5 methods.
- At `rho=0`, Mirror held-out NRMSE max was 7.9e-5, payload 3,297B; generic full matrix max 1.8e-4 at 4,001B; pair table exact at 4,773B.
- At `rho=.1`, Mirror mean held-out NRMSE .216 and generic full matrix .323.
- All payload sizes/hashes and serialized replay values verified; maximum replay error 0.
- CPU timings are from PyTorch 2.14.1 CPU; no CUDA was available.

### Interpretation

The condition×behavior address factorization can extrapolate across held-out pairs when the target functions share a rotational law. Mirror improves the storage point over the generic full-matrix model, but this is an aligned synthetic result and costs about 3× decode wall time on this CPU implementation.

### Hypothesis boundary

The experiment shows a useful synthetic representation/storage frontier, not independent capacity or natural CAST generalization. The `rho=.1` result shows that arbitrary pair-specific deviations require richer/private state.
