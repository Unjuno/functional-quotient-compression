# MA-1175 — Mirrorスーパーグラフ構造介入の修正・再実験

**2026-10-21 JST / 100 CPU訓練完了 / 主判定：共有核VJP機構PASS、正しいON/OFF判断PASS、将来学習改善FAIL、Mirror固有の品質改善FAIL。**

## 1. 何を修正して、なぜ再実験したか

MA-1174の事後監査で以下を確認したため、古い結果を上書きせず**新しい事前登録MA-1175**として検証した。

1. 以前の「干渉」は同一gateへの異なるミニバッチの符号変動で、**異なる仮想エッジが共有物理核へ与える勾配の競合ではなかった**。
2. `mirror_lookahead`は候補全てが現状維持より悪くても4経路切断を**強制**していた。
3. 6更新先読みだけでは、構造介入による長期学習への効果を測りにくい。
4. 切断の探索予算と、切断なしの通常追加学習の比較を重視する必要がある。

今回の `PROTOCOL.json` SHA256: **`e00d9848d3948ab52d52ddc7240e0dafefd513c64102d969d272295107a3f790`**。新しい教師シード **1327, 1361, 1381, 1399, 1409**、2世界×5シード×10方式=**100モデル**。train1024/dev384/fresh768/OOD768は教師・シード・splitを独立生成。Fresh/OODを生成したのは全100チェックポイントとSHA256マニフェスト確定後のみ。自然言語ではなく8次元合成関数回帰。

## 2. 正確に実装した構造と介入

- 4ノード×全有向結合×2 Mirror方向=最大**32仮想8→8→8 MLP**。2同期Loop。共有物理核128、32×4学習アドレス128、ゲート32、ノードバイアス32、合計**320学習係数**。仮想重み4096値は独立学習パラメータではない。
- 固定プログラム：4符号付き置換ページ＋Householder→tanh→逆Householder。対照は完全に同じアドレスの直接tanh変換、固定全経路、ランダム削除、小ゲート削除、共有核VJP衝突候補、同じ最終構造を最初から学習、普通のMLP、切断せず追加400更新。
- 主更新**420回**、CPU PyTorch2.10.0+cpu FP32・1スレッド・AdamW LR0.007・batch64。構造介入は更新100と230で各4経路を候補。修正版は**切らない候補も必須**。コピーした同一Optimizer状態から、同じ未来trainバッチで **H=6またはH=40** 更新し、dev損失が維持より**0.0005以上改善**する場合のみ切断。選ばれない試行の重みとOptimizer状態は破棄する。
- Shared-core VJP：各仮想MLPが2 Loop全体を通じて共有核へ与える勾配を個別に逆伝播。衝突候補は、その寄与と他経路の寄与総和が反対向きの経路を優先。再構成誤差は最大 **1.67×10⁻⁷**。**ただし反対向き寄与を持つ経路が存在しないときは、候補リスト上位4本が事実上のtie-breakになる**ため、「真の衝突経路を削った」とは呼べない。
- **H=120** は最初の切断前のモデルで、開発データだけを使う**事後機構監査**。候補の選択や新たな学習率調整には使用しない。600追加試行更新/ペアを測定・別途計上。

## 4. 事前登録判定

- **機構PASS:** 共有核のエッジ別VJP合計と全勾配が相対誤差最大`1.6666e-7`で一致。切断した経路の重みを復元・実行しない。ON/OFFと学習パラメータは区別。
- **ガードPASS:** H40の20介入中、**5回だけ切断、15回維持**。H6は3回切断・17回維持。候補が現状維持より有利になる条件を満たすときに限り切断した（H40 **20/20ルール整合**）。以前の「毎回強制切断」は修正できた。
- **学習改善FAIL (0/10):** H40 Mirrorが、H6 Mirrorと全経路維持420更新の**双方**よりFresh NMSEを5%以上低下させたペアはゼロ。H40は全維持より**4/10**ペアで数値的に改善したが、強い閾値には届かない。
- **Mirror固有FAIL (2/10):** 同条件の直接tanh構造介入より5%以上のFresh改善が出たのは2/10ペア。事前閾値7/10に不達。
- **最終構造初期学習との比較0/10勝:** H40 Mirrorよりも、全く同じ最終マスクを初期時点から使ったモデルが10/10ペアで同等か良い。平均ペア差（H40−初期マスク）`+0.002767`、記述的合成標準不確かさ `u_c=0.001449`、k=2の幅0.002898。ただし異なる教師世界5シードずつを混ぜたため、母集団の信頼区間とは解釈しない。
- **追加学習対照0/10勝:** 400個の先読み選択用clone更新を、全経路を保持した追加400実更新に回すと、10/10ペアで明らかに良い。中央値NMSEは0.066227対0.085628。演算下限MACおよび壁時計は別集計。

## 5. なぜ学習が改善しなかったか：事後診断

1. **本物の共有核競合が弱い:** H40の20介入のうち14件では、各経路の共有核勾配が**その他全経路の合計勾配に逆向き**となる経路が一つもなかった。経路ペア同士には負内積があっても、経路を一つ切れば総合的に良くなる保証はない。
2. **短期の開発損失は最終の学習利得を保証しない:** 最初の介入からH40対H120の「削るべきか維持すべきか」判定は9/10一致。しかし実際のH40構造変更は最終Freshで固定構造学習に勝てない。局所DEV改善と長期Fresh汎化は別。
3. **刈り取り前のモデルが十分な役割分化を獲得していない可能性:** 学習が生成重みと多数経路を有効利用する前に4本×2回を切っても、共有核の機能形成を改善しない。切断前の役割分担・対応する関数のユニークさを直接測っていないため、確定的原因ではない。
4. **追加試行学習の費用が高い:** H40方式は各介入時に維持1＋切断4グループ×40更新＝200更新、計**400 clone更新/モデル**を支払う。選択用の実行MAC下限中央値は約**1.82億**（実学習約2.10億、合計約3.92億）。別のH120開発監査では追加600更新・約2.83億MACを使ったため、総監査込みは約6.75億。比較の820更新全維持の約4.30億MACは**MLP部だけの下限proxy**であり、VJP/デコード・固定基底生成の演算は含まない。
5. **最終MLP品質と実効保存量:** H40は残存経路中央値30/32、packet3737 Bで、全保持3801 Bから1.68%削減したのみ。batch1 CPU推論中央値**約365 µs**、全保持約360 µs、通常MLP約15 µs。最終重み辞書/固定プログラムのコード配布量は別途必要であり、削減を過大評価しない。

## 6. 限界と次の修正候補（未実行）

**今回の失敗は、Mirror・Loop・ノード数そのものの有用性の一般的な否定ではありません。** 試験は8次元の合成教師で、Mirror方向・ノード数・Loop数は固定、介入はエッジ4本単位のみ。自然言語も学習済みAttentionも使っていない。実務判断では、まず**外部の学習済みAttentionを固定したFFN置換**か、**共有核の明確な機能干渉を持つ合成タスク**で、切断が後続学習を促す因果機構を単独に検証すべき。

候補の計算グラフ生成、切断とパケット削減、VJPを正しく実装したことは確かだが、性能や汎化の改善は確認されていない。**実装後に判定ゲートを変更せず、FAILを保持する。**
