# MA-1166 Phase E — one-vector virtual MLP batch execution vs synchronous graph updates
**Preregistered 2026-10-20 JST BEFORE any Phase E implementation, model training, or seed inspection.** Branch: `research/ma-1166-parallel-graph-phase-e-20261020`. Prior MA-1166 Phase A–D frozen; no retroactive retuning.

## Research question
(1) Can all 63 virtual edge MLP weight arrays be generated from one physical 253-float parameter *in one batched decoder call*, with **same exact function and gradients** as the earlier per-destination, sequential DAG (only floating point reduction differences)?
(2) Can all graph nodes synchronously update from the previous Loop state in one batched edge evaluation, exploiting GPU-style parallel semantics at matched 253 physical coefficients? How does it trade representation/task error for CPU compute and latency?
(3) Does the Mirror nonlinear decoder improve over the same-size affine/non-Mirror decoder at matched architecture and fixed program effects?

## Models
- `serial`: unmodified MA-1166 Phase C `VirtualSupernet.forward` (63 edge instances, 21 i<j node pairs across 6 unrolled node positions, 3 mirrors per pair, 6 native weight coordinates of width6->8->6: 110 per edge; existing residual coefficient 1.2/(3j)). **One learned physical tensor 253 floats**: 64 core, 63 gate logits, 126 learned mirror-code scalars.
- `serial_batched`: mathematically equivalent to serial, but decode all 63 virtual weights in one tensorized call instead of six smaller calls, then execute each node j sequentially. Verify outputs **and gradients** at identical theta for each decoder before training. This is the *implementation-control*; it does not change architecture.
- `sync2` or `sync6`: 7 state slots (slot0 fixed input; slots j=1..6 initialized to the input), for each parallel wave t compute 63 per-edge-view MLPs from **previous-wave** source slot values; aggregate by destination, update all six destination slots simultaneously with `h_j^{t+1}=h_j^t+(1.2/(3*j*T))*sum_(i<j,m) sigmoid(a_ijm) F_ijm(h_i^t)`; output slot6. Cannot simulate arbitrary sequential DAG in one wave; T waves have dependency. Same 253 trainable numbers, 63*T active virtual edge computations and complete all-skips connectivity; no pruning or sparsity penalties. Fixed costs and exact formula reported.
- For each of serial, serial_batched, sync2, sync6 use `mirror` and `affine` decoder; additionally native253 residual MLP (exactly 253 learned coefficients). **Total 9 modes**.
- Pairwise match initializer theta and fixed decoder seed across serial/batched/sync in each teacher/seed; keep default seeded program exact. Use original MA-1166 `GraphSpec` and `VirtualSupernet.decode`. No independent virtual weight parameters.
- Synchronous graph not assumed equivalent to serial graph. Inference must never delete any candidate edge; no thresholding, no route pruning. Correctness tests: per-dest serial-vs-batched equality and gradients; synchronous vectorized-vs-plain reference, step determinism, complete 63 edges and all gradients, exact physical scalar count, finite gradients.

## H/T/D/C/U
H1: serial_batched exact same function/grad as serial, with lower CPU forward latency; paired tests should pass abs/max <1e-5.
H2: sync2/sync6 achieve lower per-wave critical-path depth (but may incur higher active edge compute); no unconditional speedup guarantee on single-core CPU.
H3: on parallel-teacher task sync models attain superior quality than serial controls; on sequential aligned/independent, T wave discrepancy may hurt.
Decision PASS for correctness if 10+ tests pass and verification replays all finished model checkpoints. Mirror-specific performance PASS only if mirror beats affine same architecture in >=4/6 paired world-seed settings at >=5% relative NMSE and no greater payload bytes AND active operations. Failure otherwise. Pure b1 CPU runtime speedup alone is implementation evidence, not GPU proof. Training fixed updates is not capacity proof.

Caveats: 63*T active edge MLPs vs serial63; GPU batching benefit cannot be established without GPU. Attention/content retrieval is absent. Fixed random direction buffers are deterministic from a seed but depend on PyTorch RNG/program revision, so production program bytes and reproducibility are not free. A parallel-teacher positive control is intentionally aligned, not natural-task evidence.
