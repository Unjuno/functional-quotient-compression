# MA-189 — frozen backbone with two-sided Mirror task views

Status: **PROMISING**, scoped to the synthetic aligned transformation family
Branch: `research/ma-189-freeze-backbone-mirror-20261007`
Protocol frozen before fresh access at commit `08b8c7b89d38edafe48d1e25b5aeba93a485c7c6`

## H — falsifiable hypothesis

Given a frozen shared linear backbone, one input-view angle plus one output-view angle can recover a new task in the two-sided Givens family at rank-2 LoRA-level quality using no more than one quarter of its incremental inference bytes. An unrelated task map should show the boundary where private parameters are needed.

## T — execution

One 16D-to-8D Task-0 map is the shared physical backbone. For aligned worlds, Task 1 is generated by one Givens rotation of the first input pair and one Givens rotation of the first output pair. Unrelated worlds use an independently sampled matrix and bias. The frozen Task-0 output was evaluated before and after adaptation.

Each skill was fit at nested budgets of 16, 64 and 256 examples for 200 full-batch AdamW updates. Development seeds 18901/18902 selected LR 0.01 over 0.003 using the preregistered all-method, both-condition mean held-out MSE at 64 examples (0.6240 vs 0.6548). Fresh seeds 18911–18913 used only LR 0.01.

Controls: hard tie; one-sided input-only Mirror; rank-1 and rank-2 LoRA; a shared rank-2 hypernetwork with nonzero factors; and independent full weights. Inference bytes use a deterministic tensor-record codec and include the shared base and all record metadata. Resume payloads separately include optimizer state.

## D — result

**PROMISING on the deliberately two-sided-view-aligned synthetic teacher.** The preregistered 64-example aligned quality/byte/retention gate passed in 3/3 fresh worlds. This is fixed-update/sample-efficiency evidence, not a capacity result.

At 64 examples, fresh aligned means were:

| Method | Held-out MSE | Total inference payload | Incremental bytes/skill | Resume payload | Active compute proxy | Inference throughput |
|---|---:|---:|---:|---:|---:|---:|
| Two-sided Mirror | 8.87e-11 | 684 B | 55 B | 4,866 B | 1.74M | 1.01M examples/s |
| One-sided Mirror | 3.26e-2 | 656 B | 27 B | 3,857 B | 1.69M | 1.98M examples/s |
| Rank-1 LoRA | 1.94e-2 | 755 B | 132 B | 4,866 B | 1.95M | 5.28M examples/s |
| Rank-2 LoRA | 6.75e-3 | 851 B | 228 B | 5,186 B | 2.25M | 5.00M examples/s |
| Shared rank-2 hypernetwork | 6.75e-3 | 2,507 B | 1,880 B | 10,998 B | 7.17M | 1.96M examples/s |
| Independent full | 3.64e-11 | 1,213 B | 584 B | 6,210 B | 1.64M | 15.68M examples/s |

Two-sided Mirror used 0.241× rank-2 LoRA's incremental inference bytes and 0.773× its active-compute proxy. Earlier Task-0 MSE remained exactly unchanged. The actual eager CPU training wall time was about 0.162s versus 0.072s for LoRA; inference throughput was 0.20× LoRA. Thus the storage/quality frontier improved while measured runtime regressed.

Across the nested aligned sample budgets, mean MSE was 6.04e-11 / 8.87e-11 / 8.16e-11 for two-sided Mirror and 1.42e-2 / 6.75e-3 / 6.39e-3 for rank-2 LoRA (16 / 64 / 256 examples). The view code reached the teacher family with even the smallest budget; the candidate still received the registered 200 updates at every point.

The result depended on both coordinates: the input-only view used only 27 B but had 0.0326 MSE. On unrelated tasks at 64 examples, two-sided Mirror MSE averaged 2.07, rank-2 LoRA 1.20, and independent full weights 4.69e-4. Shared views did not replace private task parameters there.

The aligned teacher was constructed from exactly the two operations represented by the candidate. Rank-2 LoRA and its hypernetwork control did not fit that combined transform within 200 updates; a rank-4 LoRA comparison was not run. Consequently, these measurements support a narrow structured-family storage result, not broad Mirror-specific superiority over all adapter parameterizations.

## Fact / interpretation / hypothesis

**Facts.** At 64 aligned examples, all three fresh worlds passed the <=1.10× rank-2 LoRA MSE, <=0.25× incremental-byte, and <=0.01 Task-0 retention criteria. The observed Mirror/LoRA incremental-byte ratio was 55/228 = 0.241. At all three data budgets, the same payload sizes were used. Eager inference throughput was lower than LoRA. Unrelated task maps failed under the shared view.

**Interpretation.** Two learned angles are sufficient to identify the aligned transformation from few examples while avoiding private matrices. The byte gain includes real name/header and code costs. The view composition costs runtime in this implementation. This is a Pareto improvement in storage and task quality for the registered aligned family, with a compute/latency loss.

**Hypothesis.** A fused rotation kernel or precomputed small rotation matrices may reduce latency, but that must be tested without changing the quality/byte evidence. Rank-4 LoRA could recover the same transformation with more private parameters and is the strongest missing control.

## C — strongest counter-hypothesis

The task generator exactly matches the candidate's two-angle structure, while rank-2 LoRA is not expressive enough for a generic composition of input and output rotations and received only 200 updates. The observed gap may therefore reflect teacher/control alignment and optimization budget rather than a general Mirror advantage.

## U — unresolved

- Rank-4 LoRA and a byte-matched generic two-coordinate shared basis were not compared.
- No optimized runtime kernel was tested; CPU timings use eager PyTorch and a small linear harness.
- No natural continual-learning data, task discovery, or language-model integration.
- No near-convergence/fixed-byte frontier; this is not a capacity claim.
