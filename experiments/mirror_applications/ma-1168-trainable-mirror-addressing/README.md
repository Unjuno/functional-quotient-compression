# MA-1168 — Trainable many-to-many physical-to-virtual address mapping in batched synchronous Mirror supergraphs

**Status: PRE-TRAIN PROTOCOL. Date 2026-10-20 JST.**

**Mirror insertion:** add learnable low-description two-axis addressing code m_e to each virtual MLP edge's **logical weight generation** from a single shared physical coefficient vector, enabling each edge to read a distinct mixture of four fixed signed-permutation coordinate maps without introducing independent virtual MLP trainable tensors.

## Core question / hypothesis
MA-1167 proved that 75 virtual MLPs can share one physical tensor and train via one backward pass while all edge computations run batched within each Loop. However its source-to-virtual mapping was fixed. Can learned address selection within the same 289 physical coefficients materially improve function learning at comparable compute/serialized inference bytes?

This is *not* a fully unrestricted combinatorial neural architecture search; tests four fixed address pages with continuous two-dimensional code per virtual edge. All 75 directed edges, including self-, long-range and cyclic connections across 5 simultaneous state nodes remain active. No pruning. Three synchronous Loop steps, all inputs at t read states from t-1.

## Physical and virtual dimensions
Input/state d6, virtual MLP 6→8(tanh)→6, 110 virtual weights/edge, 5 source×5 dest×3 mirror codes=75 edges, 8,250 logical MLP weight values. One physical nn.Parameter vector of exactly 289 learned FP32 scalars, partition [global core64, 75 edge-gate logits, 75×2 per-edge address codes]. Fixed seeded core projection maps 64→110; four deterministic signed-permutation pages of its output; 2 learnable codes per edge parametrically weight the four pages. Page codes *select physical-to-virtual correspondence*. Mirror decoder uses fixed seeded Householder Q, tanh and Q inverse *on the generated 110-vector*. Code has no free dense 110×110 trainable matrices.

## Frozen methods
- **address_mirror**: learned four-page two-dimensional address; orthogonal nonlinear Householder/tanh/inverse-Householder virtual weight warp.
- **address_affine**: *same learned page and 289 scalars*, native elementwise tanh on virtual weights without rotated Mirror.
- **orientation_mirror**: MA-1167 original trained Householder orientation codes, but fixed core-to-edge projection, same 289 physical scalars.
- **native289**: ordinary residual 6→21(tanh)→6 MLP plus size-10 side parameter, same exactly 289 learned coefficients; no edge fanout.

## Training and evaluation
Worlds (a) **address_aligned**, generated by address_mirror with hidden independent randomized teacher θ plus hidden address codes and gates; (b) **native**, 6→25→6 residual teacher. Teacher weights NOT given to students. Paired 3 seeds 601, 607, 613; independent train2048/dev1024/fresh2048/OOD2048 data; ID inputs std0.8 OOD std1.6. AdamW 900 updates, lr0.012, wd1e-4, batch128, all methods same. Dev selects checkpoint, fresh accessed only for final chosen configurations. Record raw MSE and normalized MSE vs identity, full loss trajectory (0,50,100,...900), gradients by physical group, source and endpoint speed and bytes.

Oracle replay: construct address-mirror teacher and plug oracle θ/code into a student instance; this is a representability check, never training.

## Predeclared gates
H1 mechanism: all 75 views and all physical gradient groups active; alternate address codes measurably change virtual weights, full graph synchronous BMM equals scalar reference within 5e-5; oracle aligned teacher exactly reconstructed (<1e-6 FP32 max error); 24/24 checkpoint/metric replays.
H2 learned mapping improves over orientation_mirror by >=5% fresh NMSE paired in >=4/6 world/seed settings at same physical coefficient budget. Failing H2 means **no evidence learned addressing helps under this protocol**.
H3 Mirror-specific advantage over address_affine on fresh in >=4/6 settings at >=5% relative AND actual payload+active MAC no worse. H3 FAIL is separate from H2.
H4 equal physical parameter native: report all results and MAC/runtime, no hidden GPU claim.

C/U: four basis pages severely limit possible mapping; fixed seed matrices occupy runtime memory and coded seeds/program count; training fixed-update does NOT prove expressivity limit or convergence; share-all gradient collisions and nonlinear recurrence may block pointer specialization; aligned teacher gives oracle family and cannot establish natural compression; native teacher measures out-of-family stress. Preserve the MA-1167 FAIL verdict and original outputs. Final inference keeps all 75 edges; pruning/attention/sparse connection discovery not tested.
