# MA-282 — Monarch Mirror views around a shared FFN

Status: PROMISING (narrow aligned synthetic storage/runtime point)  
Evidence lane: MECHANISM / STORAGE / RUNTIME  
Base commit: `28194ea`

## H — hypothesis

One shared nonlinear FFN plus a scalar Monarch coordinate per task can express several logical FFN functions with fewer serialized bytes than independent blocks. The coordinate must be compared to per-task Monarch factors, butterfly views, IA3 and low-rank residuals. Unrelated FFNs should show where private weights are necessary.

## Selection

The eligible pool was `[MA-274, MA-278, MA-282, MA-286, MA-296, MA-299]`. Python `secrets.randbelow(6)` returned index 2, selecting MA-282. After `git fetch origin --prune`, no MA-282 remote branch existed; MA-274 and MA-278 had other-worker branches.

## T — protocol

A NumPy CPU harness uses an 8 input / 12 hidden / 8 output ReLU FFN and four logical tasks. Aligned teachers apply one scalar-controlled Monarch transform `T(m)=A1(m) P A2(m)` around the shared FFN; independent teachers have unrelated full FFN weights and uninformative cues. Task output MSE is measured on held-out Gaussian inputs.

Controls: hard tying, one-angle butterfly view, hidden IA3 scaling fitted on training examples, rank-r output LoRA fitted on training examples, per-task independent Monarch factors, and independent full FFNs. LoRA rank 4 was selected on development seeds only by mean held-out MSE across both conditions and worlds (rank 1/2 were worse). All serialized inference tensors, codes, IDs, metadata and headers are charged. Coordinate-path throughput, operator preparation and workspace are reported separately.

The first fresh result file (`source/invalidated_initial_fresh_rank_4.json`) is invalid diagnostic files are retained under `source/invalidated_*`: audits found omitted shared-base bytes/non-method-specific timing, a charged Monarch coordinate bypass, and an invalid aligned full upper control. All prior fresh outputs are retained as invalid diagnostics and excluded from claims. Final fresh seeds 28241–28243 were frozen before rerun.

## Gates

PASS for the aligned screen if all fresh worlds have held-out task MSE <=1e-5, Mirror payload <=0.5× independent full FFNs, and coordinate-path throughput >=0.5× the best matched simple control. Mirror-specific value also requires a better actual-byte/quality/compute frontier than Monarch-factor, IA3, low-rank and butterfly controls. Independent functions test the private-weight boundary. This is a fixed operator screen, not Transformer learning or capacity evidence.

## D — decision: PROMISING (narrow aligned synthetic storage/runtime point)

**Fact:** Across fresh seeds 28241–28243, aligned Mirror MSE was exactly 0 in all three worlds. One shared FFN plus four scalar view codes serialized to 925 B, versus 3,279 B for the equivalent independent full FFNs (0.282×). Four free Monarch factor vectors plus the same shared FFN also reconstructed exactly at 1,145 B. Mean coordinate-path throughput was 13.6M examples/s for Mirror and 10.7M for free-factor Monarch, with a 1,024 B prepared operator workspace for each view path. The butterfly control used the same 925 B and had mean MSE 2.09; IA3 used 1,169 B/MSE 1.48, and rank-4 LoRA used 2,373 B/MSE 1.13. Hard tying used 841 B/MSE 3.09. These are held-out output errors over 512 examples/task/world.

For unrelated functions, Mirror MSE equaled hard tying (mean 2.35), while independent full FFNs reconstructed exactly at 3,279 B. The independent Monarch view reached mean MSE 3.05. Private task weights remain necessary for unrelated functions in this construction. All methods used 2,560 examples/world including train and held-out; IA3/LoRA fit 128 examples/task only, with zero optimizer updates. The active MAC proxy and method-specific CPU throughput are in `source/fresh_upper_fixed_rank_4.json`; no GPU or language-model claim is made.

**Interpretation:** This is a narrow aligned-family storage point: a scalar address reproduces four task-specific nonlinear FFNs without duplicating the common FFN. The 3.54× byte saving versus independent FFNs comes from the aligned parameterization. The more relevant simple structured comparison is the free-angle Monarch control: the scalar Mirror code saves 220 serialized bytes and was not slower in this run. The rank-4 LoRA point is faster but has materially higher error, so the observed points trade quality, bytes and compute; the experiment does not establish a universal Mirror advantage.

**Hypothesis:** Structured one-coordinate views can provide useful multiplicity when tasks share a known transform family. Arbitrary functions still need private state. This screen does not test learned task identification or convergence.

**C — strongest counter-hypothesis:** The teacher was deliberately generated by the tested Monarch coordinate, so exact reconstruction demonstrates representational fit to a matched family, not discovery of a general compression method. A better-trained low-rank or native adapter control could improve its quality/runtime point.

**U — unresolved:** No trained Transformer/LM, natural task distribution, broad function coverage, optimized low-level Monarch kernel, operator-preparation latency under deployment, or near-convergence capacity frontier. IA3 and LoRA are fixed least-squares screens, not optimized training baselines.
