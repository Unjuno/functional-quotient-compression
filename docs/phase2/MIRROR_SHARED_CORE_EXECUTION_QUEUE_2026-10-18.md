## 3. Q2：共有核のスケーリングを調べる最小設計案

**目的：共有物理ベクトルを増やしたとき、複数の有用な機能を保てるか。Mirrorを外しても同じ結果になるか。**

最初はMLP核または単一の系列混合核のどちらか一方。Attention＋MoE＋Cross-Attentionの全部を同時に入れない。形状、入出力、活性化、集約規則、私有部分を固定した後、開発データだけで候補を絞る。

変数の定義は研究方針書の資源表に従う。候補は共有核の独立スカラー数16/64/256/1024、論理Mirror数1/2/4/8、反復数1/2/4。これは**候補範囲であり未凍結**。まず内部幅・演算精度・保存精度と1方向1反復を固定して物理次元を調べ、次に同じ物理次元でMirror数、最後に反復回数を動かす。必要な入出力ヘッド等を含む総パラメータは別に実測する。

対象は、(i)既知Mirror族の正対照、(ii)通常NNで学習可能性を先に確認した非適合課題、(iii)共有しにくい独立役割を含む負対照。前の手書き数字データの再分割は探索として扱い、完全な独立データ再現と呼ばない。確認実験には未使用のタスク／データ集合を事前固定する。

| 必須対照 | 解消する交絡 |
|---|---|
| 通常の独立MLP／Attention／専門機能 | そもそも課題が学習可能か |
| 同程度の物理スカラー数、同じ数値精度の通常NN | 単に物理予算が不足していないか |
| 総実保存量を揃えた通常NN／量子化／低ランク | コード・索引を含めて圧縮できたか |
| 同じ核・同じ反復回数でMirrorなし、FiLMまたは低ランク補正 | Mirror固有の寄与か |
| 学習済み通常重みからのMirror変換（別実験） | 直接学習失敗と表現可能性を分離できるか |

専門機能の選択は最初は固定／観測可能な役割コードで行い、全対照に同じ情報を渡す。後で学習ルータを導入する場合はルータの追加容量と計算を計上する。MoEの機能数と一度に選ぶ機能数は別資源である。

**Optimizerの順序：** まず通常AdamW等で共有核・Mirrorコードに有限勾配が届くか、数値微分に一致するか、既知の表現可能な目標に収束するかを確認する。届くが収束しない場合にだけ、コードと核の分離学習率、条件数の改善、交互最適化等を同予算で比較する。未収束から表現不可能と断言せず、表現不可能な族にOptimizerだけを強化し続けない。

## 4. Q3 / Q4：メモリ共有と反復を両立する条件

MA-691の既存続編は`experiments/mirror_applications/ma-691-lazy-kv-mirror/next_phase_20261018/`を使う。既存L0は固定済み、自然言語学習側はDRAFTである。既存プロトコルの変更ではなく、必要なら改訂版として前提を修正する。

キャッシュの識別情報にはモデル／共有核の版、元トークン列、マスク・位置符号、層、反復深さ、参照メモリの版を含める。同一の物理重みを反復していても、反復深さが違えばKey/Valueを生成する状態が異なり得る。1組のKVで全深さを代用できると仮定しない。

過去Key/ValueにView別非線形を入れる方式は、現在Queryまたは読み出し後の非線形とは分ける。前者を後者へ一般に移動できると仮定しない。Cross-Attentionの参照元が複数なら、異なる内容の記憶を一つにできるわけではない。共通できるのは同じ内容の別座標View等、検証した関係に限る。

実行時間は、初期化／JIT、prefill、View切替、1トークンdecode、一定長生成の総時間を分離。比較相手は、別KVを無駄に複製する参照だけでなく、GQA/MQA、固定変換をQ/出力へ吸収した等価実装、必要に応じMLAも含む。メモリは物理重み・KV・活性・一時作業領域・展開／コンパイル済みキャッシュを分けてピークを測る。

通常の共有反復モデルとの比較がQ4の必須条件。Universal Transformer等の既存共有深さ対照を残す。共有で落ちる能力があるときは小さな私有残差を追加して境界を測り、全共有に固執しない。
