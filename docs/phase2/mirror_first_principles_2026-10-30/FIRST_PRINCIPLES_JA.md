# Vector Mirror — 第一原理からの用途再定義と研究の選択基準

2026-10-30。**研究構想・数学的機構検証**。新しい学習実験ではない。過去MAの合否・プロトコルを変更しない。

## 0. 判断

Mirrorが有用という確信は、探索仮説として保持する。しかし科学的な結論として採用しない。目的を「多くの別機能を物理的に別々に保存する代わりに、少量の機能コードで共有計算核をプログラムすること」と定義する。最初の用途は **条件付きの非線形機能選択**、次に **Loop境界での計算選択**、MoEはそれらの固有利益を確認した後の補助とする。

## 2. 必要条件と境界

### 2.1 直交Mirrorは情報を作らない

Householder `Q_m = I - 2 u_m u_m^T` は直交で、長さ・内積を保存する。`v_m` と `-v_m` および非零の実スカラー倍は同じ反射なので、コードの見た目の距離を「新機能数」と解釈してはいけない。

実効活性化 `Phi_m(z) = Q_m^T sigma(Q_m z)` について、ReLUなら

```
Phi_m(z) = Proj_{C_m}(z),  C_m = Q_m^T R^d_{>=0}.
```

証明：`max(a_i,0)` は `min_{y_i>=0} (y_i-a_i)^2` の唯一解。直交座標変換を使うとEuclidean距離が変わらないため、座標を戻した出力は回転した閉凸錐への最近点射影である。したがって 1-Lipschitz・非拡大・冪等 `Phi_m(Phi_m(z))=Phi_m(z)`。**同じQを連続適用するだけなら、純粋なMirror-ReLU部分は最初の一回以降何もしない**。Attention/MLP/Residual更新が間に入るならこの結論は適用できない。

### 2.2 どういう入力でViewが違う機能になるか

ReLUの境界上でない点に対して

```
J_m(z) = Q_m^T D_m(z) Q_m,
D_m(z) = diag(1[(Q_m z)_i>0]).
```

証明：連鎖律で導出。Dは対称冪等、Qは直交なのでJも対称冪等。ランクは活性成分数と等しい。全成分が正なら J=I / Phi=z、全成分が負なら J=0 / Phi=0 となり、両領域でView差が消える。**符号の異なる方向が実データ上で共存し、その組合せが目的に有用な場合**にMirrorの作用する余地がある。

ReLUの非線形性は入力スケールを縮めても相対的なゲート差を残す（正の一次同次性）。tanhでは小入力で三次、SiLUでは二次の差に縮退しやすい。ただし汎化性能の勝利はどちらについても保証されない。

### 2.3 単一Viewの万能性はない

共有MLPの機能を

```
F_m(x) = B Q_m^T sigma(Q_m(Ax+b)) + c
```

と定義する。この一つのViewは、`A_m=Q_m A`, `b_m=Q_m b`, `B_m=B Q_m^T` と置いた通常の幅dのMLPに完全吸収可能。K個の構造が一致するときに限り、共有が物理保存量で得になる可能性がある：

```
P0 = dp+d+qd+q
Pmirror = P0 + Kd
Pind = K P0.
```

これは学習係数数であり、バイト・推論時間は別に計測する。また、Householder一枚なら実効上・下行列への変化はそれぞれランク1：

```
Q A = A - 2u (u^T A),
B Q^T = B - 2 (B u) u^T.
```

**結合低ランク更新はMirrorを正確に包含できる。** Mirrorが強ければ、それは同族の低ランク法より「表現力が広い」ためではなく、制約が有用な帰納バイアス・最適化・記述長を与えるためである。

### 2.4 過度な「非線形必須」主張にも注意

活性化だけを挟む `Q^T sigma(Qz)` は `sigma(z)=z` なら恒等写像。しかし**一般の共有線形核**を挟む `Q^T W Qz` は `W` と `Q` が可換でなければ元の `Wz` と異なる。これも「同じ異方的フィルターを違う方向に使う」という用途である。ただし反射一枚なら `Q^T WQ-W` のランクは高々2（展開して列空間が span(u,Wu) に含まれるため）。だから線形Mirrorでも任意の独立Expertを生成しない。

### 2.5 機能差と因果的な有用性は別

コード方向の差、ゲート符号の差、出力差は**どれも単独ではタスクに有用な機能差の証明にならない**。タスクごとの入力に対して Viewの交換・無効化・固定ランダム置換を行い、予告した機能だけが選択的に変わるか測る。未知の機能群を「別Expert」と呼んでしまわない。

## 3. 三つの用途の優先順位

1. **第一候補：条件付き非線形フィルターの共有**。明示的な条件IDやLoop段数で一回につき一つのViewだけ選び、共通演算 `A,B,sigma` を使う。物理ExpertとMoEは増やさない。重要なのは「同じ基本演算が異なる座標で必要とされる」タスクであり、完全に無関係な分類器の詰込みではない。まず教師の重みを渡さず独立の関連タスクを共同学習。
2. **第二候補：Loop境界での状態制御**。段数 t ごとにQ_tを選ぶが、繰返すブロックは共有。注意：Fが一般に非線形なら `Q_t^T F(Q_t z)` は単なるReLU射影でない。Wuらの学習可能線形コントローラJ・FiLM・結合低ランクを強い対照とする。介入で「1 hop vs 2 hops」などの操作を選択的に制御できるか調べる。
3. **第三候補：既存のMoE/Attention/KVの状態再利用**。一次候補が有用なら、物理Expertを少なくして追加Mirrorで性能保持を試す。KV-cacheの再利用は正規化・RoPE・位置変換と互換であることを別途示す必要がある。既存のNoPE/RoPE FAILを再解釈しない。

**一度に全Viewを評価すれば非線形演算回数も増える。** K Viewを持つことと、1 Viewしか実行しないことを明確に区別する。選択が本当に必要な場合にだけRouterを使用し、ルーティングコード・時間も課金する。

## 5. 第一原理に忠実な検証の段階

**L0：機構の検算（新たな学習を要しない）**
- FP64で直交性、射影の冪等性、局所Jacobian、同じQの多重表現、結合低ランクへの吸収、線形核の非可換性を検算する。`verify.py` 実行ログを添付。
- 新規のタスクで学習する前に、独立に生成した実入力分布上で活性化符号・View間機能差・勾配が機能するか確認する。

**L1：機能選択が実現可能か（教師なしの重み開示）**
- 同じ共有核に2～4つの関連操作を要求するが、全方式に真の正解ラベルだけを渡す。完全Mirror生成教師と独立生成タスクを分離し、前者は陽性機構対照のみとする。
- 最初はタスクIDを明示し、Routerの学習困難を除外。1 Viewだけ実行する。
- 対照：単純共有／FiLM／BatchEnsemble／結合rank1／小型独立MLP／固定ランダムMirror。
- **主課題は事前パイロット専用の別世界で学習予算後に非飽和であると確認**（例：最良の安価な対照のCEが0.1～0.6 nat程度）。評価用Fresh/独立seedはその時点で未使用。CEとNMSEの尺度は課題に応じて固定する。
- 段階：固定核+未知コード（コード可動性）、既知コード+未知核（核学習）、両方未知（共同学習）。ルータを導入する前に原因を同定する。

**L2：Mirror-Loop の機能分化**
- 入力だけから答えを出す、真の複数操作を要するグラフ探索・関係合成を使用。R=1/2/4、View数1/2/4。段数でView指定、Routerなしから開始。
- 介入：同じ状態から異なるViewを入れ、予測した操作のターゲットだけが変わるかを観測。Attention patchingでどの内部経路が変化したか調べる。
- FiLM・結合低ランク・線形J・非共有ブロックを保存量と実計算で比較する。自然文NLLは、この層の後に扱う。

**L3：費用対効果**
- 同一品質の下で serialized inference bytes、optimizer/training FLOPs、CPU/GPU実時間、アクティブView数を計測する。係数数やMAC proxyだけで高速化を主張しない。

## 6. H/T/D/C/U（次の正式実験で凍結すべきもの）

H: 「条件IDを別状態として与えたとき、一つの物理核＋K個の小さな直交Mirrorコードは、対応する同バイト非Mirror変調より少ない干渉で関数群を実現する。またLoop段ごとの選択的機能切替を助ける。」

T: 新しいコード・データ仕様と全閾値を訓練前に凍結。DEV選択5 seed、Fresh確認10～20新seedを暫定目安。独立したタスク族も含め、Mirror生成教師を確認の主集合にしない。保護されたFreshは全コード/checkpointハッシュを封印してから開封。

D: (1) タスク特有の正解率/CE/NMSE、(2) 条件交換の選択的因果効果、(3) 同品質の保存bytesと実時間、(4) OOD機能保持を**独立ゲート**にする。対照が飽和する判定閾値は事前の非飽和パイロットで排除。勝利には最強同費用対照とのpaired比較で、事前に定めた実用効果量を満たすことが必要。単なる「Mirrorを変えたら出力が違う」はPASSにしない。

C: 結合低ランクが常にMirrorを包含するため、表現力での一方的な利得はない。適切なFiLM/BatchEnsemble、データ共有、追加計算、稀な正解ラベル漏洩だけで観測差が説明できる可能性。Mirrorで保持できないprivate成分が必要なタスクもある。

U: 入力・教師分布、seed/ハイパラ選択、意味上のfeature-ID定義、CPU/GPU数値差、クロック非固定、実装カーネル。確認試験から得たpaired効果の標準不確かさu_cとk=2の記述的範囲を報告する。ただしseed間の独立性・分布仮定が成立しなければ95%信頼区間とは呼ばない。
