# Householder Mirror family diagnostic (2026-11-09)

## Fact

- MA-701 tested 16 synthetic linear task Views generated by products of 1/2/4/8 Householder reflections around one shared 64x64 matrix. Output NRMSE against independent full task matrices was <=1.74e-7. r=4 used 19.01% of independent bytes at 1.125x matrix-vector FLOPs. Native Householder used the identical representation and exact payload hash.
- MA-702 tested 16 routed logical experts built from one shared two-layer 64-wide FFN plus output Householder Views. r=1 used 9.02% of independent FFN bytes at 1.016x MAC proxy and matched within 9.31e-8. Hard tying and same-budget FiLM missed output quality. Native Householder again exactly matched function and payload.
- Both teacher families were constructed from Householder maps; neither is trained task-quality evidence.

## Interpretation

Short Householder codes give a strong storage/compute feasibility frontier against duplicated matrices, but every measured gain is already explained by standard Householder/OFT-style parameterization around shared weights. The experiments establish no Mirror-specific extra functional freedom.

## Strongest counter-hypothesis

The codes work because the target functions lie in the exact Householder family by construction. More general task or expert updates may require longer products or private residuals, erasing the savings.
